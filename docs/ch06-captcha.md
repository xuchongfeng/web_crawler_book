# 第 6 章 验证码与挑战页

验证码、滑块、整页挑战一旦出现，多半表示：**这次访问已经被当成可疑流量**。风险引擎先打分，题是低分之后的门槛，不是第一道门。所以工程重点是**少触发**，不是把题解得更快。过了一题，分往往还在；下一页继续出，解题账单和延迟一起涨。

少触发有两层：授权、频率、出口与会话绑在一起（6.3）；以及**对抗过检**——客户端和协议不要自己暴露「我是脚本」（6.4）。已经出了，再分类、记账、降级；授权范围内才谈识别或 Unlocker（6.8）。过检讲概念、一致性和工具地图；对着未授权站「过 WAF」的操作序列仍不写（第 1.5 节）。自建 Demo 用假挑战壳或厂商测试钥匙即可。

## 6.1 形态图谱

先会分类，再对方案。名称以对方页面或厂商文档为准。

**出题型。** 图中字符、点选物体、简单算术。reCAPTCHA v2 的选图、国内大量「算一下 / 输字符」都属这类。看起来像「认一下就能过」，实际常跟会话、出口绑在一起：过了一题，分仍然低，下一页还出。

**交互型。** 滑块、拼图、转体、点选语序。极验、网易易盾、腾讯天御的行为式验证多走这条。题面是交互，判定往往在服务端看整段行为，不是本地是否对齐。Arkose（FunCAPTCHA）一类 3D / 自适应谜题也在这档。

**无感 / 行为分。** 页面上没有题。reCAPTCHA v3 给 0–1 分，由你设阈值；Cloudflare Turnstile、部分企业版 hCaptcha 在后台做浏览器质询。你这边的表现是：偶发 `403`、空壳 HTML、字段缺失，而不是一张图。

**整页挑战。** 状态码可能是 `403`、`429`、`503`，正文却是「正在确认你是真人」、Cloudflare 挑战页、AWS WAF CAPTCHA 或站点自定义拦截页。和「接口真的 503」要分开：前者是策略，后者是故障。

**登录后的二次验证。** 短信、邮箱、设备确认、二次密码。这是账号与身份问题，采集侧不要在这里自动「接着跑」。通道怎么接、红线在哪，见[第 7](ch07-accounts.md)–[8](ch08-abuse-lines.md) 章。

**App 侧证明。** 设备完整性、安装来源、nonce 校验失败时，客户端会停在验证或直接拒绝协议。点到为止，分析只针对自有 Demo（第五部分）。

识别用**你自己的契约**，不要靠「像不像验证码」的形容词：

- 状态码 + 标题 / 已知拦截模板（写进配置，而不是写进正则丛林）。
- 正文和黄金样本比：该有的列表字段没了，多了一段挑战壳。
- 厂商脚本或站点自己的错误码（用于分类，并决定 6.8 走哪条方案）。

同一次失败不要既记 `403` 又记「成功但解析为空」。分类错了，5.4 的降级会走错分支。

## 6.2 出验证码，说明已经被打低分

把挑战当监控信号，不要当一道 OCR 作业。`report` 里单独记 `error="challenge"`，并带上形态（出题 / 交互 / 无感 / 整页）。一次粘性租约上连续出挑战，优先怀疑这条**身份组合**（出口 + 会话 + 账号），而不是「题变难了」。

解题只处理题面——打码、本地 OCR、把截图发给多模态大模型，都是这一档。无感和整页挑战常常根本没有可提交的「答案」；交互型过了本地对齐，服务端仍可能拒绝。触发率没降、只是识别费或 token 费在涨，说明你在给已经被标记的流量续命。

若某个**未授权**目标「不过验证就拿不到数据」，停，回第 1.3 节。换题、换号、换设备才能继续，本身就是「已被识别」的证据。

## 6.3 少触发：比解题优先的工作

看板的主指标是**触发率**（6.7），不是识别通过率。触发率下来了，6.8 里那些解题产品可以不买。

授权采集里，先做这些「不靠过检也能少出题」的事：

1. **换门，而不是换题。** 官方 API、合作导出、对方加白（IP / 账号 / 约定 UA）是零触发的正路。
2. **先慢。** 按主机限 QPS、退避、错峰、增量而不是全站重爬（第 3.6、2.6 节）。很多题是频率打出来的。
3. **身份不要自己拆开。** 粘性出口与 Cookie、`httpx.Client`、浏览器 Context 同生共死（第 4.2、5.3 节）。登录后乱轮换出口，比「QPS 略高」更容易出挑战。
4. **出口按任务配，不按「最像人」买。** 直连或机房够用就不要升档；升档写进预算，并确认你有权采集（第 4、5.4 节）。
5. **浏览器当例外。** 已有接口就不要开 Playwright 去硬扛页面风控（第 3.4 节）。
6. **账号用授权测试号，且不要和出口错配。** 新号 + 机房 + 高频，是经典低分组合。号源与养号节奏不在本书范围（第 7–8 章）。

做完上面，触发率仍高：先看客户端是否自己漏了自动化痕迹（6.4），再查发布和误报。不要先加识别配额。

用打码把未授权站「磨」到不出题、靠换号压挑战，不是少触发，是把已经被识别的流量续命。

## 6.4 对抗过检：让分不要掉到出题

过检的目标与 6.3 相同：**少出验证码**。差别是这一层处理「对方看见的客户端像不像它所期望的浏览器 / App」。`httpx` 默认的 TLS 握手、头集合、`navigator.webdriver`、Chrome DevTools 协议痕迹，都可能单独把分打低，这时还没有题可解。

所以顺序是：6.3 把频率和身份摆正 → 6.4 把客户端对齐 → 仍出题才进 6.5。过检成功，题不出现；过检失败再解题，是倒着做。

**对方大概在看什么（概念，用来对表，不是配方）：**

| 层 | 常见信号 | 采集侧常见露馅 |
|----|----------|----------------|
| 传输 | TLS 指纹（JA3 / JA4 一类） | Python / Java 客户端的握手不像 Chrome |
| HTTP | 头的集合、顺序、Client Hints | UA 写 Chrome，没有对应的 Sec-CH / Accept 语言 |
| JS 环境 | `webdriver`、`chrome` 对象、插件、语言、时区 | 自动化默认打开这些缺口 |
| 协议控制面 | CDP / WebDriver 启动序列 | Playwright、Selenium 的控制通道本身可被记 |
| 渲染 | Canvas / WebGL / 字体 | 无头或模板机千篇一律 |
| 行为 | 点击间隔、滚动、焦点 | 0ms 连点、瞬间填完表 |
| 绑定 | 出口地域 vs 时区 vs 语言 vs 账号 | 住宅 IP 在东京、系统时区在上海、Cookie 刚从机房来 |

原则是**自洽**：你声称的浏览器、出口、语言、时区、账号历史要能对上。改一项、其余还是脚本默认值，分往往更差。第 5.3 节的租约绑定，就是过检的身份部分。

**业界常用的几条路（2026 年仍常见，效果会过期）：**

1. **换栈，而不是先改指纹。** 目标只看 HTML、且主要卡在 TLS 时，用会模仿浏览器握手的 HTTP 客户端（如 [curl_cffi](https://github.com/lexiforest/curl_cffi)），比开浏览器便宜。必须跑页面脚本时，再用真浏览器。
2. **真浏览器，减少自动化外壳。** 系统里的 Chrome 经 CDP 驱动（[nodriver](https://github.com/ultrafunkamsterdam/nodriver) 一类）、或给 Playwright 打补丁减少启动痕迹（[Patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright)）。默认 Playwright / Selenium 最容易在控制面露馅。
3. **改过引擎的浏览器。** [Camoufox](https://camoufox.com/) 这类在 Firefox 引擎侧改渲染与环境，用来对齐 Canvas / WebGL 等 JS 补丁补不到的层。体积大、要跟版本，当例外而不是默认。
4. **托管过检。** Scraping Browser、Web Unlocker（6.8）等于把 2+3 和出口买成一次请求。贵，且不改变授权问题。
5. **行为不要像回放。** 授权操作里留出正常人的间隔和滚动；不要为了 QPS 在同一 Context 里瞬间点完所有按钮。这不是「鼠标轨迹生成器」，是别用脚本默认的零延迟。

旧的 `playwright-stealth`、`undetected-chromedriver` 仍会出现在教程里，维护节奏跟不上对方规则时会突然全军覆没。选型看仓库是否还在更新，并在**自建靶场**上复测，不要迷信某年某篇「过 Cloudflare」评测。

**靶场怎么练：** 在你自己的 Demo 上打开几项检测（例如记录 TLS 指纹、是否 `webdriver`、头是否自洽），用 `httpx`、默认 Playwright、再换一种过检栈各打一次，看板看触发率差在哪。对象是你的检测逻辑，用来理解「分从哪掉的」。

**写到地图为止。** 本书不提供：JA3 对照表、CDP 隐藏清单、Canvas 噪声参数、滑块轨迹、以及把上述组合打到未授权商业站 / 过 WAF 的步骤。那些是第 1.5 节的操作序列。需要对接具体库时，用该库文档 + 你的 Demo。

## 6.5 已经出了：限速 → 换出口 → 人审 / 授权解题

和第 5.4 节同一条链。题已经出现，说明少触发这一档漏了；这里是补救，不是主路径。

1. **限速。** 该域名 QPS 降下来，退避加长（第 3.6 节）。很多挑战是频率引起的，先慢，再动出口。
2. **换出口。** 冷却当前 `(出口, 域名)`，`acquire` 同等级下一条。仍挑战：看预算是否允许升一档；不允许就不要升。乱轮换粘性会话，会把挑战变成账号异常（第 4.2、5.3 节）。
3. **人审或授权解题。** 队列里留下：URL 或任务 ID、租约、出口、账号标识、挑战截图或 HTML 摘要。处置人是**你有权操作的环境**里的值班、内部审核台，或合同写明可用的识别 / Unlocker（6.8）。不是默认外包打任意站点。
4. **停 / 熔断。** 触发率超过阈值（6.7），任务先不发。池和账号还在，别为了消化队列去加压。补救之后必须回到 6.3 / 6.4，把触发率打下去，而不是长期靠第 3 步续命。

人审的主产出是**处置**（降 QPS、停任务、修 Demo、查部署）。若走了授权识别，答案字符串只活在这次请求里，不要进数仓当「题库」。

账号批量失效、短信爆量，不要在这一层用「再注册几个号」补。那是[第 8 章](ch08-abuse-lines.md)的红线。

## 6.6 自有验证码回归

你能合法、可重复解题的地方，首先是**自己的产品**（或书面授权、厂商给的测试通道）。

**测试钥匙与开关。** Google reCAPTCHA、Cloudflare Turnstile、hCaptcha、国内各家企业控制台，都提供始终通过 / 始终失败的测试密钥，或 staging 开关。CI 和采集回归用这些。需要无挑战的联调，走测试环境，不要把生产放行后门写进爬虫。

**回归要证明两件事：** 该出的时候出（防护没被误关）；测试钥匙或白名单生效时，授权流量能过。缺前半段，哪天防护坏了没人知道；缺后半段，你的采集和 e2e 会在自己的挑战页上误报。

**负荷。** 对自建靶场加压，直到挑战出现，确认 6.7 的计数在涨、降级有动作。这是在验观测和「少触发、过检是否生效」，不是在练破第三方题。

## 6.7 触发率看板

主指标是触发率，不是解题通过率。没有看板，挑战会假装成「解析偶发为空」，解题账单也会假装成「正常成本」。按**域名**（再按出口等级、任务类型、方案类型）看：

- 挑战次数 / 总请求，以及绝对次数（低流量时百分比会骗人）。
- 与 `429`、硬 `403`、超时拆开。
- **过检栈切换**（`httpx` / 真浏览器 / 托管）前后的触发率差。
- **解题次数、通过率、每成功动作费用**——走了 6.8 的识别或 Unlocker 才有。费用猛涨而触发率不降，说明该回到 6.3 / 6.4，而不是加配额。
- 和 QPS、发布、出口变更对齐。
- 人审队列深度和平均处置时间。

告警看**斜率**。自建 Demo 上，用「每 N 次请求返回挑战壳」就能把曲线跑出来，不必接真厂商。

## 6.8 方案图谱

名单会过期，品牌会更名。下面是 **2026 年 8 月** 仍能公开打开的对照，用来选型，**不是通过率排行**。评测文和打码站博客多带分销链接。先问「我是站点方还是采集方、有没有授权」，再点进某一格。

**按角色选，不要按「哪家更能过」。**

| 你的位置 | 方案顺序（从该做的做到贵的） |
|----------|------------------------------|
| 站点方 / 要给自己的产品加防护 | 选一家验证码厂商 → 测试钥匙 + 服务端校验 → 和登录风控共用分数 |
| 授权采集、合作导出 | 官方 API / 加白 → 限速与粘性 → 过检对齐客户端（6.4）→ 人审 / Unlocker（最后才解题） |
| 自建靶场、CI | 假挑战壳；或厂商测试钥匙；自研简单图可加本地识别 |
| 未授权的第三方生产站 | 停（第 1.3 节）。下面任何一格都不能把这件事变成合法 |

### 站点方：防护产品

前端出题或无感，**服务端必须校验 token / 分**，只信前端等于没接。国内用户为主，优先看国内厂商连通性；海外站或已在 Cloudflare / Google 生态，看 Turnstile / reCAPTCHA。

| 产品 | 官网 | 怎么读 |
|------|------|--------|
| Google reCAPTCHA（v2 / v3 / Enterprise） | [google.com/recaptcha](https://www.google.com/recaptcha/) | v2 出题，v3 给分由你设阈值，Enterprise 偏风控平台。大陆常用 `recaptcha.net` 镜像；隐私与加载要自己测。 |
| Cloudflare Turnstile | [cloudflare.com/turnstile](https://www.cloudflare.com/application-services/products/turnstile/) | 无感向、有免费档。已用 Cloudflare 最好接。国内加载不稳定时不要当唯一门。 |
| hCaptcha | [hcaptcha.com](https://www.hcaptcha.com/) | 偏隐私表述的出题 / 企业风控，流程与 reCAPTCHA 同类：组件 → token → 服务端验。 |
| 极验 GeeTest | [geetest.com](https://www.geetest.com/) | 行为式滑块 / 点选，国内电商金融常见。 |
| 网易易盾 | [dun.163.com](https://dun.163.com/product/captcha) | 无感 + 滑块 / 点选等，文档按 Web / App / 小程序拆。 |
| 腾讯天御验证码 | [cloud.tencent.com/product/captcha](https://cloud.tencent.com/product/captcha) | 云账号体系内接入，国内连通性通常好。 |
| 阿里云验证码 | [aliyun.com/product/captcha](https://www.aliyun.com/product/captcha) | 同上，按量、多种形态，跟阿里云账号走。 |
| Arkose（FunCAPTCHA） | [arkoselabs.com](https://www.arkoselabs.com/) | 高风险流程上的自适应谜题，企业合同。 |
| AWS WAF CAPTCHA | [AWS WAF 文档](https://docs.aws.amazon.com/waf/latest/developerguide/waf-captcha-and-challenge.html) | 规则触发的整页挑战，适合已经在 AWS 的站点。 |

选型看：受众地域、要不要无感、服务端校验是否好做、无障碍（读屏 / 语音）、宕机降级。不要为了「防爬」选最难的交互，把正常用户一起赶走。

### 采集与测试：授权通道

这些不是破题技巧，是**对方或厂商允许你走的门**。

1. **官方 API / 合作库。** 仍是第一选择（第 1.3 节）。有文档和配额时，不要在挑战页上堆方案。
2. **加白。** 出口 IP、测试账号、约定 UA、时间窗。写进合同和双方看板，比任何识别都稳。
3. **测试钥匙 / staging 开关。** 6.6。Playwright、e2e、采集回归都走这里，不要在生产密钥上关防护。
4. **内部人审台。** 浏览器里点一次，会话留下，后续请求继续。适合低频、高价值、你有权登录的后台。
5. **托管 Unlocker / Scraping Browser。** 你发目标 URL，供应商在自己一侧做出口、过检和挑战重试，退回 HTML 或 JSON。公开产品例如 Bright Data [Web Unlocker](https://brightdata.com/products/web-unlocker)、Oxylabs [Web Unblocker](https://oxylabs.io/products/web-unblocker)，以及同类解锁 / 浏览器 API。按成功请求计费，单价通常高于普通代理。只用于合同允许的目标；不把未授权变成授权。接到工程里：单独预算、`report` 记 `unlocker=true`，触发率异常先熔断。它是买来的 6.4，不是 6.5 的替代品。

### 识别与打码市场

市场上常见三类形态，大模型属于第一类的一种实现，不是单独的过检层：

| 类型 | 你交给对方的 | 你拿回来的 | 典型适用 |
|------|--------------|------------|----------|
| 图 → 字 / 坐标 | 验证码图片或截图 | 字符串或点击位置 | 自有或授权的出题图；质量回归 |
| 其中：多模态大模型 | 同上，外加一句「图上是什么 / 点哪几个」 | 同上 | 题面多变、不想维护题型模板时；贵、慢 |
| 站点密钥 → token | 页面 URL + site key 等公开参数 | 厂商要的 token | 厂商组件型验证；仅授权目标 |

**图识别（国内常叫打码）：** [超级鹰](https://www.chaojiying.com/)、[图鉴](http://www.ttshitu.com/) 等，按题型计价，人工校正或模型，秒级返回。老教程里的「若快」一类品牌会消失，付款前核对主体，和代理市场同一纪律（第 4.5 节）。

**Token / 协议识别（国际站谈得多）：** [2Captcha](https://2captcha.com/)、[Anti-Captcha](https://anti-captcha.com/)、[CapSolver](https://www.capsolver.com/)、[CapMonster Cloud](https://capmonster.cloud/)、[YesCaptcha](https://yescaptcha.com/) 等。有的偏人工兜底（覆盖面宽、更慢），有的偏模型（更快、题型一变就回退）。单价公开页常见「每千次数美元」量级，企业题更贵。自建高量另有本地授权软件（如 CapMonster 本地版），算的是许可证 + 你的机器，不是 API 按次。

**本地识别。** 开源 OCR、自训小模型，只适合**你控制的简单图**（自己的 Demo、自己产品里还没下线的字符码）。用来测「这题是不是已经弱到失去防护意义」，或给你的回归当开关。

**大模型识别。** 把题面截图或原图发给多模态模型（云端 API 或本地 VLM），让它读字符、选物体、回答「点哪几个」。和超级鹰、图鉴是同一类接口：进图、出答案；CapSolver 等 token 服务背后也有模型，只是不经过你的提示词。它**是一种解题方法**，优点是少维护题型模板，换一套出题文案往往还能认；代价是：

- 延迟和单价通常高于专用打码，还叠模型输入里的图片 token。
- 对**出题型**有时够用；滑块 / 转体要的是轨迹和时序，模型给一个「答案字符串」不够；reCAPTCHA v3、Turnstile、整页 JS 挑战常常**没有图可送**，送了也过不了服务端质询。
- 图和页面上下文进了第三方模型，等于多一次数据出境，授权与隐私要单独算。
- 过完题，风险分往往还在。Agent 在浏览器里「自己看图再点」同样是 6.5，不是 6.4。

自建靶场可以：自己的字符图 → 你的模型或 API → 填回 Demo。不要把未授权站的生产题批量丢进公有大模型。

**接到采集里怎么摆：** 做成独立适配器，和 `httpx` 脚本分开。调用前已经走过 6.3–6.5；调用后 `report` 记费用与是否通过。日配额打满就停。触发率不降就关掉适配器，先修 6.3 / 6.4。对象必须是自有题、书面授权的测试题，或合同允许的采集目标。

**到此为止，不往下写：** 某厂商 task 类型怎么填、token 嵌回第三方页面的字段名、滑块轨迹怎么生成、浏览器扩展怎么自动点。那些是过他人防护的操作序列。需要对接时，用**该识别商文档 + 你自己站点的测试钥匙**在靶场里做，不要对着生产站抄博客。

### 自建靶场最小方案

不必买识别，也不必买 Unlocker：

- 第 N 次请求返回固定挑战 HTML，练分类、少触发（把 N 调大）和 6.5。
- Demo 上打开一两项「像不像脚本」的检测，对比 `httpx` 与一种过检栈的触发率（6.4）。
- 一张你自己生成的字符图 + 可选本地 OCR 或一次多模态调用，练「图 → 字」适配器。
- 厂商测试钥匙，练 token 在**你的**服务端怎么验。

出门考（自建靶场）：

1. 给 Demo 加一种挑战壳，爬虫能 `report(error="challenge")` 并带形态。
2. 写出三条 6.3 的改动（降 QPS、粘性、加白），再写一条 6.4 的过检改动（例如换栈），分别量触发率。
3. 已经出了再走 6.5；说明解题为什么不能代替过检。
4. 从 6.8 的表里为「授权采集」写一行顺序：零触发 → 少触发 → 过检 → 最后才解题。

第二部分到此结束。出口和挑战都是身份的外围信号；下一章进入账号本身——只用你拥有或被授权的测试号。
