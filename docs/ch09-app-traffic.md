# 第 9 章 App 流量与抓包

第四部分从这里开始。网页至少还能打开开发者工具；App 里列表往往不在 HTML 里，而在客户端发出的请求里（第 2.5 节）。本章只解决：流量可能是什么形状、在**你自己的设备与 Demo** 上怎么接到、HTTPS 在开发构建里怎么处理。签名字段怎么认、怎么在 Demo 上复现，留给第 10 章。

对象仍是第 1.5 节：本机 / 模拟器、你控制的 Demo App、合作测试包。商店里随便下一个包来做中间人，不在范围内。绕过商业证书固定、内存 dump，本书不写。

能在**你的服务端**看到同一条请求时，优先看服务端日志，不必先上中间人。

## 9.1 REST / gRPC / Protobuf / 长连接

先判断形状，再选工具。抓到一堆看不懂的字节，多半不是「加密了」，而是编码变了。

**REST / JSON over HTTP(S)。** 和网页 Ajax 最近：方法、路径、头、JSON body。App 里常见区别是：Host 不是你在浏览器里看的那个；鉴权在头里而不是 Cookie；错误码在 JSON 里而状态仍是 `200`。这一档用 HTTP 中间人就能读。

**Protobuf。** 二进制字段编号，没有 JSON 那种键名。抓包软件会显示「application/x-protobuf」或一串不可读 body。要还原，需要 `.proto` 或你自己服务端的描述符——自有 Demo 里这两样你都有。没有描述符时，只能先记路径、长度、何时出现，字段含义放到第 10、15 章对照。

**gRPC。** 多半跑在 HTTP/2 上，消息是 Protobuf，还有 `grpc-status` 一类尾头。中间人必须能解 HTTP/2；有的工具默认只解 HTTP/1.1，会表现为「连上了但一片空白」。流式 RPC 是一串帧，不是一次 request/response。

**长连接。** WebSocket、gRPC stream、部分 MQTT / 自建 TCP。列表可能是「先连上，再推增量」，而不是反复 GET。抓包要按**会话**看帧，不要按「每个 URL 一行」去套网页爬虫的心智。心跳、重连、过期，都是会话问题，和 Cookie 过期同类。

同一 App 里四种都可能有：登录走 JSON，列表走 gRPC，通知走长连接。任务文档里写明「这条业务走哪一种」，不要假设全是 REST。

## 9.2 抓包拓扑（自己的设备与 Demo）

拓扑选得对，证书那一节会省很多事。从稳到脆：

1. **服务端日志 / 接入层。** Demo 的网关、Nginx、应用日志。TLS 在你的证书上终结，客户端抓不抓得到都无所谓。能走这条就走这条。
2. **App 内调试通道。** Debug 构建把请求打到 Logcat / Console、Flipper、各端 Network Inspector。只对开发包开放，和生产证书固定不冲突。
3. **HTTP 中间人。** 设备或模拟器把代理指到你电脑上的 [mitmproxy](https://mitmproxy.org/)、Charles、Proxyman、HTTP Toolkit 等。流量：`App → 你的代理 → Demo 服务器`。代理装的是**你的实验 CA**，只给这台设备和这个 Demo 用。
4. **系统抓包。** Wireshark / tcpdump 看 IP 和端口、确认有没有连错 Host。HTTPS 内容在这里仍然是密文，除非你在服务端或中间人层已经解密。

真机与模拟器都可以。模拟器改代理省事；真机要和电脑同一局域网，或用 USB 反向代理。云手机若供应商已提供抓包口，用他们的口，不要再套一层来路不明的「万能解密」。

**不要做的拓扑：** 把中间人插进别人的生产 App 和别人的服务器之间，再想办法让系统信任你的 CA。那是在拆别人的传输层。合作测试包若对方要求走他们的抓包环境，用他们指定的，并写进授权记录。

一次会话记清楚：App 版本、设备、代理软件版本、是否 Debug 包、出口（直连还是第 5 章租约）。第 10 章对照签名时，缺一条就会对不上。

## 9.3 HTTPS 与证书（开发构建）

HTTPS 中间人能看见明文，前提是**客户端愿意信任你的实验 CA**。开发构建把这件事做进配置；生产包默认不信任用户证书，有的还做证书固定（pinning）。

**Android。** 目标 SDK 24 起，应用默认不信任用户安装的 CA。Debug 包用 `network_security_config` 的 debug-overrides，允许用户 CA 或仅允许你的实验证书。这是官方调试手段，写在你们仓库的 debug 资源里，不要打进 release。

**iOS 模拟器 / 开发证书。** 把实验 CA 装进这台模拟器或这台开发机的信任设置。ATS（App Transport Security）在 Debug 里可对你们自己的 Host 放宽，同样不要带进商店包。真机开发包走你们的 provisioning，不走越狱。

**鸿蒙等。** 拓扑相同：开发构建信任实验 CA 或看服务端日志。各端菜单名字不同，原则不变。

**生产包 + pinning。** 看见「证书错误 / SSL handshake failed」，先换 Debug 包或改看服务端，而不是上 Frida 去摘固定。绕过商业证书固定的步骤，第 1.5 节不写。合作方只给了 release 包、又不许改构建时：请他们开抓包通道或提供服务端日志，而不是在客户端对抗。

实验 CA 的私钥当密钥管（第 7.9 节）：不进 Git、不装到非实验设备、用完吊销。中间人会看到登录 Cookie 和 Token，日志留存按附录 D。

## 9.4 和网页采集的差别

| | 网页（第 3 章） | App（本章起） |
|--|----------------|---------------|
| 第一眼 | 开发者工具 Network | 没有这层共识，要自己接拓扑 |
| 正文 | 常是 JSON / HTML | JSON、Protobuf、gRPC 帧混用 |
| 会话 | Cookie 罐 | 头里的 Token、设备 ID、游客令牌（第 7.6 节） |
| 改版 | 选择器失效 | 路径还在，字段编号或签名变了 |
| TLS | 浏览器已信公共 CA | Debug 才信实验 CA；release 可能 pinning |
| 批量 | 直接重放 HTTP | 客户端可能参与签名，重放要等第 10 章 |
| 触发 | 打开 URL | 有的列表必须先完成一段 UI（第 11 章） |

相同的部分不要丢掉：先找接口再渲染（第 3.2 节）、限速与幂等（第 3.6 节）、出口与会话同生共死（第 5.3 节）。App 不是「换一个 Charles 就能通」；通了之后仍是采集系统。

出门考（自有 Demo App + Debug 构建）：

1. 指出列表数据走 REST、gRPC 还是长连接；若是 Protobuf，拿出对应 `.proto` 或服务端描述符。
2. 画一张拓扑：流量经过谁、TLS 在哪终结。能走服务端日志就写明为什么没上中间人。
3. Debug 包能在中间人里看到一条列表请求；release 包若失败，解释你**没有**去绕 pinning，下一步是看日志还是换构建。
4. 同一条请求，记下 App 版本与是否 Debug，留给第 10 章对照。

通过即可进第 10 章。下一章把抓到的流量收成接口文档，并在 Demo 上辨认时间戳、nonce、body hash。
