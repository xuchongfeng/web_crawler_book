# 第 11 章 客户端形态与 UI 触发

第 10 章假定：列表请求已经能在协议里重放。有的数据必须先完成一段交互（点 Tab、过引导、选门店），请求才会出现。本章只回答：客户端可能是什么壳、这段交互用什么点、**点完之后批量仍走协议**。

篇幅压短。Appium、Airtest 的定位器百科不写；对象仍是自有 Demo / 授权测试包。未授权群控刷量见第 8.5、1.5 节。

能在协议里直接调的，不要开 UI（和第 3.4 节「何时才用 Playwright」同一句）。

## 11.1 原生、RN / Flutter、小程序、WebView

形态决定流量从哪冒出来，不决定「必须用 UI 采」。

| 形态 | 流量常在哪 | 对采集的含义 |
|------|------------|--------------|
| 原生（Kotlin / Swift 等） | 自有 HTTP / gRPC 栈 | 抓包 + 第 10 章文档即可；UI 只为触发少见 |
| React Native | JS 桥 + 原生网络 | 列表多半仍是普通 HTTPS；别被「是 JS」骗去爬页面 |
| Flutter | Dart 自己的 HTTP；有的走平台通道 | 中间人照常；控件树不是 DOM，UI 自动化更脆 |
| 小程序 | 微信 / 支付宝等宿主的请求 | 抓包在宿主与开发者工具里；批量看官方接口与授权，不要模拟点击刷 |
| WebView | 就是网页 | 先当第 3 章做；混合包里原生和 Web 可能各走各的 Host |

同一产品可以几种叠：壳是原生，列表在 WebView，登录在 RN。任务写明「这一屏的数据从哪条协议来」，不要按 UI 框架选爬虫栈。

## 11.2 iOS / 鸿蒙差异清单

Android 不是唯一实验场。换端时先对这张表，再谈第 9.3 节的证书。

| | Android Debug | iOS 开发包 | 鸿蒙开发包 |
|--|---------------|------------|------------|
| 代理 | 模拟器改 Wi-Fi 代理较省事 | 模拟器可装实验 CA；真机走你们的 provisioning | 真机 / 模拟器改代理，菜单名不同 |
| ATS / 明文 | `network_security_config` | ATS 默认禁明文；Debug 只对自有 Host 放宽 | 类似的明文与证书策略，看官方文档 |
| UI 自动化 | Espresso / Appium UiAutomator2 | XCUITest / Appium XCUITest | 官方自动化与 Appium 支持在变，先查当前文档 |
| 包形态 | APK / AAB | ipa + 签名 | hap / 应用包；渠道与权限模型不同 |
| 后台限制 | 各厂商省电不一致 | 后台联网更严，长连接易断 | 后台与联网权限单独申请 |

采集任务钉的是**这一端的 Debug 包版本**，不是「Android 通了 iOS 自然通」。协议若两端共用，第 10 章文档可以一份；证书、触发、后台保活仍要分端验证。

## 11.3 Appium / Airtest：只用于触发和拿会话

[Appium](https://appium.io/)、[Airtest](https://airtest.netease.com/)（以及 Espresso、XCUITest）在本书里的职责只有两件：

1. **触发：** 走到那条协议请求会出现的界面（登录后的某 Tab、选完筛选项）。
2. **拿会话：** 把 Cookie、Token、设备上的登录态交给第 7、10 章的脚本——或确认 Demo 已处于「已登录」再切协议采集。

不是：用控件树把每一页列表点一遍当爬虫。那又慢又脆，费用和风控都差，和「用 Playwright 硬扛整站」同一类错（第 3.4 节）。

脚本结构建议：UI 流程单独一个短任务（有超时、有截图、失败就停），成功后 `release` 的是「界面已就绪」；拉数任务不再碰控件。设备租约见第 19 章，本章不把群控当触发方案。

定位器只钉你 Demo 上稳定的 `content-desc` / accessibility id，不要钉像素坐标。坐标在 Flutter、小屏、暗色模式下会整批碎。

## 11.4 批量仍然走协议

判断句：**UI 换会话，协议换数据。**

| 步骤 | 走哪一层 |
|------|----------|
| 登录、过引导、选一次站点 | UI 触发（11.3） |
| 翻页、增量、全量列表 | 第 10 章协议 + 第 5 章出口 |
| 对方改了按钮文案 | UI 脚本修一处；拉数不应停 |
| 对方改了签名或分页 | 修协议文档；不要加更多点击 |

出门考（自有 Demo）：

1. 指出一屏数据来自原生、WebView 还是小程序宿主。
2. 若必须点击：写一段「只触发、不拉列表」的步骤；列表用第 10 章脚本拉完两页。
3. 用一句话解释：为什么不把 Appium 循环当成采集主循环。

第四部分到此结束。协议侧已经能在 Demo 上稳定拉数。下一章进入制品：源码和包从哪来，以及先判断有没有稳定接口。
