# 第 24 章 助手、路由与 Agent 边界

第 23 章把抽取收成规则和可评测的模型。本章把「谁来决定下一步」写清楚：助手帮人看 Diff 和值班摘要；路由在协议 / 浏览器 / 真机 / 人工之间升级；Agent 按 **cost per action** 计价，过不了门口的评分就不要跑。

第八部分不是「用大模型重写爬虫」。目标仍是授权 Demo 与合同内任务。Agent 去未授权站点开、自动过验证码、伪造画像，第 1.5、6 章不写。

## 24.1 解析器、Diff、值班摘要

助手默认是**只读的**：读黄金集 Diff、读失败样本、读看板，产出人能核对的说明。它可以建议改哪条选择器，但合并进解析器仍要过 23.2 的 CI。

三件具体工作：

- **解析器辅助：** 给定一条失败的原始响应和 Schema，标出空字段、像挑战页还是像改版。不要直接改生产解析器。
- **Diff：** 新旧解析器或新旧钉扎对同一批原始包出表。摘要应列出「哪些主键的哪些字段变了」，而不是一段散文。
- **值班摘要：** 把第 22.2 节五列里变红的项收成几条：哪个域名、哪类错误、建议停哪条队列。摘要里不带 Token、不带完整身份证号。

助手可以跑在内网。提示词里塞进未脱敏仓储全文，等于绕过 23.3。需要上下文时，只给 Schema、字段名、脱敏片段。

## 24.2 路由：协议 / 浏览器 / 真机 / 人工

调度选执行器，按成本从低到高爬梯子。每一级升级都要有**可观测的失败类型**，不要「偶发 403 就开 Playwright」。

| 级 | 何时用 | 失败后 |
|----|--------|--------|
| **协议 worker** | 10.1 稳定、无设备约束 | 字段不像挑战 → 第 23 章；像挑战 → 第 6 章降并发，不是立刻升浏览器 |
| **浏览器** | 必须执行页面脚本或偶发渲染（第 3.4 节） | Context 与出口同生共死（第 5.3 节）；仍无接口则停或人工，不要无限点 |
| **真机** | 必须客户端才发请求、账号设备绑定（第 18.3、19 章） | 锁和账号成对；UI 只做短触发（第 11.3 节） |
| **人工** | 二次验证、合同要求人审、黄金集争议、闸门拿不准 | 工单关闭前任务保持暂停；人审结果写回血缘 |

路由配置写在任务上（「允许升到哪一级」），不要写在某个 worker 的 if 里。升到真机要同时能 `acquire` 设备与授权号；拿不到就排队，不要降级成未授权号。

挑战页、封禁：先当信号减配额，路由可以停在协议层。把验证码「升级」成 Agent 识图打第三方题，是第 6.8、1.5 节的红线。

## 24.3 Agent 与 cost per action

Agent 指：模型多步调用工具（开页、点、读、再决定）。每一步都是一次 action，账单是 token + 浏览器时 + 出口 + 可能的云手机。第 2.6 节已经说：Agent 尤其贵，且过不了门口的评分。

**门口评分。** 任务进 Agent 之前用廉价信号否决：不在允许名单、配额已尽、规则解析仍绿、成功率低是因为钉扎过期而不是「需要智能」。评不过就不要创建 Agent 会话。

**cost per action。** 给每类任务设上限：例如 Demo 上允许 N 步、金额 M。打满停，人接。不要用「再试一次就能找到接口」当无限预算。和 22.2 的费用列同一科目，单独告警。

Agent 的工具箱只开放：你们的 Demo URL、只读仓储查询、提交人审工单。不要给它任意 URL、任意 shell、任意 ADB。成功标准仍是 Schema 校验 + 黄金集，不是「模型说完成了」。

能规则或单次模型抽取解决的，不要上多步 Agent。能协议解决的，不要上 Agent 去点 UI。

## 24.4 反模式

和全书红线同一方向，写在路由和 Agent 上以免「智能」把闸门拆掉。

- **一把梭：** 所有任务默认 Agent + 浏览器 + 最高档出口。
- **无限步数：** 失败就再想再点，直到预算或风控先爆。
- **用 Agent 过检：** 打第三方验证码、编指纹、编 TLS 画像。
- **升维逃避钉扎：** 协议红了不冻结队列，让 Agent 去装「最新包」。
- **把仓储全文丢给公有云：** 绕过 23.3。
- **助手直接改生产：** 跳过黄金集 CI。
- **路由写死在执行器：** 每个 worker 自己决定升真机，调度无法限流。
- **人工当免费 Agent：** 二次验证工单没有 SLA，也没有「暂停任务」状态，号在设备上挂着烧锁。

判断句：**助手帮人做决定；路由按失败类型升级；Agent 是最贵的执行器，必须先过评分和预算。** 第八部分结束。下一章用同一套模板把案例写全，方便复盘。
