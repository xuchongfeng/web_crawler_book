# 第 7 章 授权账号工程

从这一章起进入第三部分。出口和挑战是身份的外围；账号是对方用来认「你是谁」的主键。Cookie、Token、设备绑定、风控分，多半挂在这个主键上。

本章先把开户形态分开：邮箱、手机、匿名 / 游客。每一种都有授权做法，也有市面上的灰产做法。授权路径写进池；临时邮箱打第三方、接码、伪造游客号，只作分类，步骤留给第 8 章点名、不写操作（第 1.5 节）。

没有登录也能完成的任务，先走游客或公开接口，不要为了「像有账号」去造号。官方 API 或对方加白够用时，实名账号池可以是空的。

## 7.1 账号在采集里的位置

一次已登录请求，对方至少看到三件绑在一起的东西：

- **会话：** Cookie 或 `Authorization: Bearer …`。丢了或和出口拆开，就像换了一个人（第 3.1、3.7、5.3 节）。
- **设备 / 客户端：** 浏览器画像、App 设备 ID、是否和上次登录同一台。真机与云手机的绑定见第 19 章。
- **账号档案：** 注册时长、是否验证过邮箱短信、近期是否密集验证、是否刚换过出口。

风控分是这三件的联合，不是「密码对了就 200」。新号 + 机房 + 高频，是第 6.3 节写过的经典低分组合。登录后的短信 / 邮箱二次验证，按挑战记账，不要在采集里自动「接着跑」。未登录的游客令牌也是一种身份，见 7.6。

工程含义：账号不是字符串清单，是**带会话和绑定约束的租约**。池的形状跟第 5 章出口池对齐：`acquire` / `report` / `release`。

## 7.2 只使用三类号

进池之前先过这一关。说不清来源的，不要写进配置。

| 来源 | 什么意思 | 典型用途 |
|------|----------|----------|
| 自有测试号 | 你在自己的产品或 Demo 上注册并持有 | 靶场、CI、本书出门考 |
| 企业测试通道 | 公司为测试开的号、沙箱、staging 种子账号 | 内部联调、授权采集打自家预发 |
| 合作方提供 | 合同或工单写明的测试账号、只读账号 | 对方站点的授权拉取 |

「我自己在某商业 App 上注的号」只在**你就是该产品用户、且平台规则允许自动化**时，才接近第一类。多数用户协议禁止批量、禁止脚本。吃不准就当不能用，改走官方 API 或书面授权。

不要进池：临时邮箱打出来的第三方号、接码号、买来的「成品号」、未经书面同意的私人号。官方游客令牌可以进池，角色标成 `guest`（7.6）。第 8 章解释灰产名词为什么踩线。

每条账号记录至少有：开户形态（邮箱 / 手机 / 游客）、来源（上表哪一类）、所属环境、用途、过期或回收日、能否登录自动化。来源栏空着的，校验当失败。

## 7.3 三种开户形态

对方要「一个身份」，不一定要「一个实名用户」。采集里先对上形态，再谈池。

| 形态 | 对方常见门槛 | 授权侧怎么做 | 市面上还有、本书不写操作的 |
|------|--------------|--------------|------------------------------|
| 邮箱注册 | 验证链接或邮箱 OTP | 自有域名别名、公司测试箱；自己的 Demo 可批量 | 十分钟邮箱 / 临时邮打第三方批量注册 |
| 手机注册 | 短信 OTP、有的要本机卡 | 自持实名卡；云厂商给**你产品**的测试号 | 接码、号段贩子、用他人身份办的卡去刷注 |
| 匿名 / 游客 | 无登录也能拉一部分数据 | 走官方游客接口；自有 App 的游客号由你后台发 | 反推第三方游客生成规则后批量伪造 |

三种都可以进 7.8 的池，但租约上的 `role` 和绑定不一样。游客往往没有邮箱短信，却仍有设备 ID 和出口。混在一个「账号」字段里会把冷却和风控记错。

## 7.4 邮箱注册：自有别名可以批量，临时邮不能当号源

邮箱解决的是「验证落到你控制的收件箱」。**在自己的产品或书面授权的测试环境里**，用自有域批量开测试号是正路，不是灰产。

**授权批量：** `test+shop01@你的域`、通配收件、公司测试箱。信还是你的，审计、离职回收都走得清。给 Demo / 预发开 50 个只读号，走这条。别名不是匿名：对方和邮件服务商都看得到主域。

**临时邮箱。** 十分钟邮箱、公开转发箱一类，市场上就是为了「用完即弃」。隐私场合有人用；拿它去**第三方站点批量注册**，是第 8.1、8.3 节的号源问题：平台禁止、号极容易进垃圾段、还常连带诈骗和滥用。本书不写临时邮 API 怎么对接、怎么打进别人的注册接口。

采集脚本只读**你有权读的箱子**（IMAP / 厂商 API / 测试后台回显）。自建靶场能免收邮件就免：接口直接返回验证码，或后台一键已验证。

## 7.5 手机注册：自持卡是测试号，接码是号源

短信门槛比邮箱重：号段、实名、是否插在「像手机」的设备上，都会进风控分。

**自持卡。** 你自己实名办理、合同在你名下的手机卡，包括你合法办理的内地卡、香港卡、境外当地卡。数量就是你办了几张，用途是你自己的产品测试或少量授权登录。卡和设备、出口绑在一起（第 19 章），不要把同一张卡的验证码分给十个脚本。港卡 / 境外自持卡**不会**因为卡本身变成无限号池。

**云厂商测试号。** 你是短信业务的甲方时：阿里云 / 腾讯云 / 华为云的测试手机号、AWS SNS 或 Twilio 的 sandbox / magic number、一键登录测试通道。验证码在控制台或文档里，用来回归「你的产品发得出」。不是给第三方站点收短信。

**接码与号段贩子。** 把别人的（或虚拟的）号租给你收 OTP，国内常叫接码，也有海外号、语音接码。这是号源市场，不是测试通道。对第三方批量注册、养号，法律和平台风险见第 8 章。本书不写平台名单怎么挑、怎么接 API、怎么配香港卡套餐去刷注。未授权目标遇到短信墙，按第 6.2 节停。

自建 Demo：固定验证码或测试库回显。出门考不必插真卡。

## 7.6 匿名 / 游客账号

不少 App 和站点允许**未登录**访问列表、详情、搜索；有的会先发一个游客 Token 或设备号，再按这个身份限流。这不是残缺登录，是第三种身份。

**先当门，不当号。** 公开接口或官方「游客初始化」能拿到的数据，走它（第 1.3、3.2 节）。能匿名完成的任务，不要升到邮箱 / 手机注册。`acquire(role="guest")` 借的是一条游客会话，不是一个注册用户。

**官方游客接口。** 客户端启动时调用的 init / guest / anonymous，返回 Token 或 `device_id`。你用自己的 Demo 或授权测试包，按文档调一次、把会话放进租约，这是产品设计的路径。游客仍然要和出口、设备绑定：同一游客令牌换出口乱飞，分一样会掉。

**分析生成规则，只打自有 App。** 游客号常是 UUID、设备指纹摘要、或带签名的短 Token。在**你能控制两端**的 Demo / 自有后台里，可以读自己的规则、从测试接口批量签发，用来压测和采集回归。这是 7.2 的「自有测试号」，只是角色叫游客。

**不要做的：** 从第三方 App 里反推签发算法、伪造 `device_id` / 游客签名、批量灌号去绕过「每设备一份额度」。那是造身份，和接码、临时邮批量注册同一类红线（第 1.5 节、第 8 章）。第五部分看自己的包、对照请求，对象仍是自有制品，不是商店里随便下一个包来造游客。

游客池的上限按对方文档或你的授权来，不要按「规则我分析出来了就能无限发」。额度用尽：降并发或走合作接口，而不是换一套生成器。

## 7.7 只自动化自有 Demo / 自有后台的注册登录

登录自动化的对象，默认只有：

- 你写的 Demo 或练习站；
- 你们产品的预发 / 测试后台；
- 合同写明允许脚本登录的测试环境。

对上述对象，第 3.7 节那条会话链路在这里扩成可重复：注册（若需要）→ 登录 → 把 Cookie 或 Token 交给同一个 `httpx.Client` 或同一个浏览器 Context → 过期刷新或重新登录 → 登出或作废。OAuth / SSO 用该环境的测试应用凭证，不要拿生产客户端密钥。

**不要自动化：** 第三方站点的批量注册、短信过验证、扫码登录接力。崔庆才书里的「模拟登录」章节可以用来理解 Cookie 和表单，练习场换到你的 Demo。

二次验证出现时：人审或测试钥匙（第 6.5、6.6 节）。脚本里写死「收到短信就填」只允许打**你自己的**测试通道（7.5）。游客初始化按 7.6，不要在这里假注册。

## 7.8 账号池：租约、冷却、与设备 / 出口绑定

和代理池同一套口令，脚本里不要另写一份账号字典。

```python
lease = accounts.acquire(
    domain="demo.example",
    role="reader",           # guest / reader / … 按 Demo 角色，游客走 7.6
    sticky_seconds=3600,
    bind_egress=True,        # 与第 5 章租约一起申请、一起还
)
# lease.account_id / lease.session
accounts.report(lease, ok=True, status=200, error=None)
accounts.release(lease)
```

**`acquire`。** 按形态和角色发：游客、邮箱号、手机号不要混成一种库存。同一号未还清前不借给第二个任务。声明了 `bind_egress` 的，出口租约和账号租约成对创建（第 5.3 节）。拿不到就排队，或降级到官方游客 / 无需身份的任务，不要默默换一个注册号硬撞。

**`report`。** 登录失败、会话过期、二次验证、封禁，分开记账。二次验证记 `challenge`，不要记成「换号」。连续失败先冷却这个号，再怀疑出口。

**`release`。** 归还会话。粘性窗口内同一任务可续借；换任务先还。进程崩溃要有超时回收，否则号会被租约耗尽。

**冷却键**建议 `(账号, 域名)`，必要时加上出口：同一号在站点 A 被限，不一定在你的 Demo 上坏了。硬失败（密码错、号已删）进隔离，等人修，不要自动重试到锁死。

**绑定。** 已登录的号不要中途换出口、换设备、换 Context。真机上的号跟设备走，见第 19 章。多个 Context 共享一个登录态，等于告诉对方「同一个人开了很多窗」——只有你有意如此时才做。

账号池的容量按**授权数量**设上限（自持卡有几张算几张，游客按官方额度）。不要按「任务有多少」去补号。号不够：降并发、拉长周期、找对方加白，而不是上临时邮或接码。

## 7.9 凭证保管与轮换

密码、Cookie 罐、Refresh Token、邮箱 IMAP、短信控制台密钥，都按密钥管，不按业务配置散落。

- **不进 Git。** 仓库里只有变量名；值在环境变量、CI 密钥或密钥管理服务（各云的 KMS / Secrets Manager、HashiCorp Vault 一类）。
- **最小权限。** 采集用只读号；能改价、能提现的号不进自动池。生产密钥不出现在采集配置里（第 6.6 节对验证码密钥同一条）。
- **轮换。** 密码和长期 Token 有过期日；人离职、合同结束、Demo 重建，立刻作废并 `release` 所有租约。Cookie 当短期会话，不要当永久密码存。
- **审计。** 谁在何时 `acquire` 了哪个号，打到哪个环境，日志留得下来。附录 D 的检查表会用到。
- **本机。** 开发机上的 `.env` 不进压缩包、不进聊天窗口。演示用一次性号，用完删。

代理密码、隧道 token 已在第 5.2 节跟租约走；账号凭证同一习惯。

## 7.10 出门考：自建站测试账号池 + 会话复用

在你控制的站点上完成，不要打公共注册页。

1. 用 7.3 的表，为 Demo 标出：哪些接口走游客，哪些要邮箱号，有没有手机号；每条号写上来源（7.2）。
2. 邮箱号用自有域别名批量开（7.4）；不要接临时邮。
3. 实现 `acquire` / `report` / `release`；游客与登录号分角色；租约与出口同生共死。
4. 故意让一个登录号失败或出二次验证：冷却生效；游客任务不受影响。
5. 若 Demo 有游客 Token：只从你的测试接口签发，写明不分析、不伪造第三方游客规则。
6. 凭证只从环境变量读取；用一句话说明为什么不接码、不上临时邮打第三方。

通过即可进第 8 章。第 8 章把临时邮箱、接码、养号、批量注册、伪造游客号摊开成边界，不提供操作。
