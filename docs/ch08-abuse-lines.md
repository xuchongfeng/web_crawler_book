# 第 8 章 账号滥用红线

第 7 章把授权路径写进池。本章只做一件事：把市面上常和「账号」绑在一起的灰产名词摊开——是什么、风险在哪、本书为什么停在名词、叠上代理池和群控时哪几种组合直接踩线。

不提供号源、接码、养号、打第三方批量注册、伪造游客号的操作。读完应能在方案评审里指出「这一步已经不是采集工程」。实验纪律见第 1.5 节；条文检索走第 1.4 节和附录 D。

## 8.1 这些词分别指什么

名称以行话为准，用来对表，不是采购清单。

**临时邮箱。** 用完即弃的收件地址：十分钟邮箱、公开转发箱、一次性域。隐私场合有人用来少留痕迹。采集语境里多半是：不持有该域、无法审计、用来通过第三方注册验证。和自有域 `+` 别名不是一类（第 7.4 节）。

**接码 / 海外号。** 把短信 OTP 租给你收。号可能来自虚拟号段、境外卡池、或他人设备上的卡。语音接码是同一市场的变体。和「你名下的自持卡」「云厂商给你自己产品的测试号」不是一类（第 7.5 节）。

**批量注册。** 脚本对**第三方**站点反复走注册接口，用临时邮或接码过验证，目标是号的数量而不是你作为用户的一次开户。对自己 Demo / 预发用别名开测试号，是第 7.4、7.7 节的授权批量，不在此列。

**养号。** 让新号看起来像「用过一段时间的真人」：登录几天、刷内容、绑设备、再拿去采集或转手。节奏、脚本、号商话术，都是在经营虚假使用记录。授权测试号按合同用、坏了就修或作废，不需要养。

**伪造游客号。** 对方给未登录流量发的游客 Token / `device_id`，本应按官方 init 接口领取（第 7.6 节）。伪造是：反推签发规则或签名，在本地批量生成，用来绕「每设备一份」的额度。和你在自有后台签发测试游客，不是一类。

**成品号。** 别人已经注册、验证、有时养过再卖给你的账号。来源、实名、是否盗号，你说不清。

这些词常打包出现：临时邮或接码 → 批量注册 → 养号 → 成品号上市。游客伪造是另一条「不注册也要很多身份」的线。打包本身就是信号：你要的不是会话工程，是号厂。

## 8.2 法律与平台风险

技术上「能注成功」不等于能用、能存、能再分发（第 2.7 节）。账号滥用至少会碰到这几层，具体条文不在这里复述。

**合同与平台规则。** 用户协议、开发者协议几乎都禁止：批量注册、转售账号、自动化创建身份、用虚拟号绕验证。违反的直接后果是封号、封设备、拒绝接口，以及民事诉讼、合作终止。不需要先构成犯罪，项目已经停。

**身份与通信。** 接码、他人实名卡、伪造游客身份，可能涉及冒用他人身份、破坏技术措施、未经许可的国际通信或短信通道。号段来源说不清时，你很难证明「我只是测试」。

**数据与系统。** 对第三方批量注册、灌游客号，常伴随高频打注册接口、验证码接口，可能落到未经授权访问、干扰系统的讨论里。拿到的若含个人信息，还有分类保护和最小必要的问题。

**连带。** 成品号、养过的号，可能已经用于诈骗、刷量、盗用。买来放进池，审计时你接得住「号从哪来」吗？

风险不因「我只爬公开页」而消失：公开页若必须挂着一个你不持有的身份才能看，身份这一层仍然要过第 1.3、1.4 节。

## 8.3 本书明确不写

遇到下面这些需求，停在名词，不写步骤、不写平台怎么挑、不写 API 怎么接、不写节奏表：

- 临时邮箱、接码、海外号、语音接码的获取与对接；
- 对第三方站点的批量自动注册、扫码登录接力、短信墙怎么过；
- 养号天数、行为脚本、成品号买卖；
- 从第三方 App 反推并批量伪造游客 Token / `device_id`。

不是因为「不好使」，而是：对象是他人身份体系和防护，做成流水线就和接码养号同一类红线。第 6 章对打码、第 4.5 节对来路不明的住宅网，同一纪律。

需要对接邮箱或短信时，只走第 7.4、7.5 节那种**你是甲方**的通道，并且打你自己的 Demo 或书面授权环境。

## 8.4 合法替代

第 7.2 节的三类号，对应到本章的词，替代关系是：

| 你以为需要 | 先换成 |
|------------|--------|
| 临时邮打第三方 | 官方 API / 合作导出；或自有域别名打**自己的**注册 |
| 接码、海外号 | 云厂商给自有产品的测试号；自持实名卡（有几张算几张） |
| 批量注册别人的站 | 对方加白、测试通道、数据合同 |
| 养号 | 授权测试号按角色使用；坏了隔离、作废、重开测试号 |
| 伪造游客 | 官方游客 init；自有 App 由后台签发；额度不够就降并发 |
| 成品号 | 合同约定的测试账号，来源写进池 |

加白、只读账号、沙箱种子，比任何号厂都稳，也更便宜——你付的是沟通和合同，不是验证码和封禁。能匿名完成的任务，连替代都不必上，走 7.6 的官方游客即可。

## 8.5 与群控、代理池叠用时哪些组合踩线

单独看，代理池（第 5 章）和设备实验室（第 19 章）都是工程能力。和本章的号源叠在一起，有的组合直接变成刷量厂。

**踩线（不要做）：**

- 接码或临时邮 × 批量注册 × 代理轮换：每个号一个新出口，专门用来把「新号」养过去。
- 成品号 / 养过的号 × 群控多开 × 未授权刷量：设备农场的经典画面，第 1.5 节点名。
- 伪造游客 × 每条出口一个假 `device_id`：用身份生成器打穿「每设备限额」。
- 授权号 × 中途乱换出口或设备：号本身合法，绑定拆开后会把分打爆，也像盗用（第 5.3、7.8 节）。这一条是工程错误，先修绑定；若再叠接码，就升格成本章红线。

**可以叠（授权范围内）：**

- 第 7 章的测试号 × 第 5 章的粘性出口：租约成对申请、成对归还。
- 官方游客 × 直连或机房：能匿名就不要升档。
- 自有 Demo 的测试号 × 你控制的设备或模拟器：第 19 章的群控对象是你的实验室，不是去刷第三方。

判断句：出口和设备在放大**你已经有权使用的身份**，还是在给**你说不清来源的身份**做掩护。后者停。

出门考（纸面即可，不必真去买号）：

1. 用 8.1 的词，标出某个（虚构或真实的）方案里出现了哪几个；对照 8.4 写出替代。
2. 指出一种 8.5 的踩线组合，说明为什么「有代理池」不能把它洗白。
3. 你的 Demo 账号池若被要求「再补 200 个号」，写你会拒绝什么来源、接受什么来源。

第三部分到此结束。身份的授权边界已经划完；下一章进入 App：流量在客户端里，抓包只打你自己的设备和 Demo。
