# 第 16 章 Frida：授权调试器

静态工具（第 13–15 章）看的是包里的代码。有的值只在**发出请求的那一瞬间**才出现：规范化之后、哈希之前的字符串，或一次调用栈。本章把 [Frida](https://frida.re/) 当成**授权调试器**：附加到你们自己的 Debug 进程，枚举、看栈、打请求前日志，再和第 9 章中间人对上同一条请求。

它不是采集主循环，也不是给商店包「揭秘」的万能钩子。第 10.3 节已经说过：能改源码打日志、能看服务端验签，就不要上 Frida。密钥你已经有，不需要从进程里掏。

对象：自有 Debug 包、你们控制的模拟器或实验室设备、合作方**书面允许动态调试**的测试包。Release 加固包、第三方商店包、用 Frida 摘证书固定或绕过反调试，本章和第 1.5、14.5 节都不写。

## 16.1 附加、枚举、调用栈

官方文档会变，菜单以你本机 Frida 版本为准。采集里用到的只有三下，且都打在**已经在跑的 Demo 进程**上。

**附加。** 设备或模拟器上先装着你们的 Debug 包，进程起来之后再 attach。版本：电脑上的 Frida 与设备上的 `frida-server`（或你们打进 Debug 包的 Gadget）必须一致。Gadget 只允许编进**你们自己的 Debug 构建**，和 debug CA 一样不进 Release（[第 9.3 节](ch09-app-traffic.md)）。不要把 Gadget 打进第三方 APK，也不要用 spawn 去抢壳的初始化窗口——那是第 14 章不写的脱壳作业。

**枚举。** 列出已加载的 Java 类、native 模块，确认你们的包名、`Sign` / 网络层类、自研 so 在不在。目的是对上第 13、15 章定位到的符号，不是把整机模块扫一遍当报告。混淆后的短名用第 15 章的 mapping 还原后再 hook；不要对着 `a.b.c` 猜。

**调用栈。** 在你们自己的方法入口打印栈，看是谁在拼请求：Activity、拦截器，还是 JNI。栈是给 10.1 文档补「调用点」的，不是为了找反调试函数去补丁。

Android Studio 的调试器、Logcat、Flipper 能回答同一问题时，优先用它们。Frida 的位置是：临时探针、不方便改包再编一次、或要同时看 Java 与自研 so 的交界（第 17 章）。它不替代第 9 章抓包，也不替代第 10 章的接口说明。

## 16.2 自有 Debug 包上的请求前日志

只钩**你们仓库里的函数**：例如拼好规范化字符串、尚未做 HMAC 的那一层。打印这串（不要打印密钥），确认和第 10.3 节服务端校验用的是同一规则。

示意（包名、类名换成你们 Demo 的；这不是通用「hook 所有哈希」脚本）：

```javascript
Java.perform(function () {
  var Sign = Java.use("com.example.demo.Sign");
  Sign.build.overload("java.lang.String").implementation = function (canonical) {
    console.log("[demo] canonical=" + canonical);
    return this.build(canonical);
  };
});
```

这和在源码里打 `Log.d` 等价，只是不必重编。能改源码就改源码，日志级别和留存按附录 D：测试密钥、Token 不要进长期日志。

**不要钩的：**

- 系统 SSL / 证书校验、OkHttp 的 `CertificatePinner`——那是 unpinning，第 1.5 节不写。中间人走 Debug 的 `network_security_config`。
- 第三方 so 里的 HMAC、密钥读取、`JNI_OnLoad`——第 1.5 节；自研 so 见第 17 章。
- 「所有 `update` / `doFinal`」这类扫盲式钩子。范围必须是你们的类。

合作测试包没有源码、但书面允许动态调试时：只对对方指出的类打日志，记录授权范围；对方禁止 hook 就停，改看他们的抓包通道。

## 16.3 与抓包对照

一次列表操作，三份材料并排：

| 来源 | 你该看到 |
|------|----------|
| Frida / Logcat（请求前） | 规范化字符串、将要发出的路径和业务字段 |
| 中间人（第 9 章） | 同一条 HTTPS 的方法、路径、头、body 或 proto |
| 服务端日志（若有） | 收到的字段、验签成败 |

对得上：10.1 文档可以定稿，采集脚本用服务端同一套规则生成 `sign`（10.3）。对不上：先对时钟、编码、是否多了空格或 Token，不要先怀疑「要不要 hook native」。

Frida 里看见明文、中间人失败：回到第 9.3 节换 Debug 证书配置，**不要**用 Frida 去摘 pinning。Frida 里对、中间人也对、脚本不对：问题在采集侧的规范化，不在调试器。

记元数据：App 版本、是否 Debug、Frida 版本、中间人软件版本、设备。第 18 章要靠这些复现，而不是靠一次不可重复的 hook。

## 16.4 反调试：现象与停手，不写绕过

Debug 包默认允许调试。你们若在 Demo 里加了检测，或合作包带了壳的配套检测（第 14.2 节），附加 Frida 时可能出现：

- 进程立刻退出、闪回桌面。
- Logcat 里出现 debugger / tracer / 注入相关字样后自杀。
- 进程还在，但列表请求不再发（环境检测卡在网络层之前）。
- attach 失败：端口连不上——先按官方文档检查 `frida-server` 是否在**你们的**模拟器上、版本是否一致，而不是理解成「必须隐身」。

看见上述现象：**记一笔，停手。** 下一步是换未加检测的 Debug 构建、用 Android Studio 调试、或看服务端日志（第 14.3 节同一套决策），不是去补丁检测函数。

**不写：** 改名 `frida-server`、藏 maps、过 `ptrace` / `isDebuggerConnected`、反反调试、用 Frida 对抗商业壳。第 14.5 节的边界在这里只引用，不展开步骤。教学壳（14.4）也不要加反调试——加了，本章的出门考会变成绕过练习，而这正是本书要避免的。

## 16.5 出门考：Frida 与 mitm 对上同一请求

自有 Demo Debug 包 + 第 9 章中间人 + 同一测试服：

1. 附加到已运行的 Demo 进程；枚举到你们的网络 / 签名类（混淆则先 mapping）。写出 Frida 版本与包名。
2. 在你们自己的「规范化之后、哈希之前」打一条请求前日志；密钥不出现在日志里。
3. 触发一次列表：Frida 日志、中间人记录、（若有）服务端日志，三份对上同一路径和同一条 `sign` / 业务字段。把对照表补进 10.1。
4. 说明：没有 hook 证书校验，没有对第三方包或商业壳附加，附加失败时选择了换构建或停手而不是绕过反调试。

通过即可。还要看 native 如何被 Java 调起，进第 17 章——对象仍是自研 / 教学 so。
