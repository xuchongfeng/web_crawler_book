# 第 3 章 精简基础（自检即可跳过）

这一章只回答：进第二部分之前，你是否已经具备最小闭环。会了就跳；某一节卡壳，用崔庆才《Python3网络爬虫开发实战》或 Mitchell《Python网络爬虫权威指南》补对应主题，本书不重写 urllib、四种解析库或 Scrapy 入门。

实验仍遵守第 1.5 节：流量打向你控制的 Demo 或许可明确的练习环境。

## 3.1 HTTP、Cookie / Session / JWT

你应能不查手册说出：

- 方法与幂等直觉：`GET` 读、`POST` 提交；不要假设「刷新一定安全」。
- 常见状态：`2xx` 成功、`3xx` 换地点、`4xx` 你的请求不被接受、`5xx` 对方出问题。采集里 `403`/`429`/`401` 比 `200` 更常决定下一步。
- 头：`Host`、`User-Agent`、`Accept`、`Cookie`、`Authorization`、`Content-Type`；重定向后 Cookie 是否还在。
- **Cookie / Session：** 服务端用会话标识认出你；客户端把 Cookie 存起来，下次带上。丢了 Cookie，就像换了一个人。
- **JWT：** 常见于 `Authorization: Bearer …`。过期、刷新、多端作废，都是会话问题，不是「再 GET 一次」。

自检：对你的 Demo 抓一条登录后的请求，能指出会话是 Cookie 还是 Bearer，过期后会发生什么。细节看两本参考书的 HTTP / 登录章节。

## 3.2 先找接口，再考虑渲染

浏览器地址栏里的 HTML，经常只是壳。列表、价格、下一页，多半来自后续 XHR 或移动端同类 JSON。

工作顺序：

1. 开发者工具 → Network，按 XHR/Fetch 过滤，看哪条响应里已经有你要的字段。
2. 复制为 cURL，改成代码里的一次请求。
3. **只有**接口不稳定、必须点选或必须执行页面脚本时，才打开浏览器（3.4）。

自检：在自建列表页上，能指出数据来自文档本身还是另一条 API。Ajax 分析方法见崔庆才第 5 章一类材料，此处不展开。

## 3.3 最小工具：httpx + 一种选择器

本书默认栈：

- 请求：`httpx`（同步够用先同步；要并发再上客户端的 async，见 3.6）。
- 选择器：会 **一种** 即可——HTML 用 XPath 或 CSS（`parsel` / `lxml`），JSON 用字典取值。不要四种库轮流写一遍。

```python
import httpx
from parsel import Selector

r = httpx.get("https://your-demo.example/list", timeout=15.0)
r.raise_for_status()
sel = Selector(text=r.text)
titles = sel.css("h2.title::text").getall()
```

JSON 接口往往比 HTML 更适合当主路径：字段名稳定、分页清楚。自检：用上面这个量级的代码，对 Demo 拉下一份列表，不引入浏览器。

## 3.4 何时才用 Playwright

浏览器贵：启动慢、占内存、费用高，还多出一套和出口绑定的会话（第 2.3、第 5 章）。

**才用：** 关键数据只在渲染后出现，且你暂时找不到等价接口；或必须完成一段短交互才能拿到会话。

**不用：** 已经有 JSON；只是「页面好看」；想用浏览器硬扛风控。后者不是基础问题，见第 2.4 节和第 6 章。

自检：能用一句话说明「这个 Demo 为什么开 / 为什么不开 Playwright」。Selenium / Splash 等对照放附录 A，正文不并列实战。

## 3.5 一种能复盘的存储

先选定**一种**能回答「上次到底存了什么」的介质：JSON Lines、SQLite 都可以。要求是：

- 每条记录带：URL 或业务主键、抓取时间、原始或规范化字段。
- 换解析器之后，还能对上旧文件做 Diff。
- 不要一上来就上 Elasticsearch + RabbitMQ；那些是第七部分的事。

自检：重跑同一列表，能指出哪些是新行、哪些是重复。MySQL / Mongo 等对照见附录 A 与参考书存储章。

## 3.6 限速、重试、退避、幂等

并发还没上代理池，也要先有这四条，否则一扩就伤对面、也伤自己：

- **限速：** 按主机限制 QPS，而不是「线程开满」。
- **重试：** 只对可能瞬时的失败（超时、`5xx`、部分网络错误）。`404`、明确的 `403` 不要盲目重试。
- **退避：** 失败后等待加长，避免同步打穿。
- **幂等：** 同一主键写两次，结果仍正确；重试才安全。

`aiohttp` / 协程原理用参考书补。本书后文把限速和配额放进调度（第 21 章），这里只要你在单机脚本里做过。

## 3.7 带着会话把请求跑通

登录一次，把 Cookie 或 Token 交给**同一个** `httpx.Client`（或等价会话对象），再去拉需要登录的页。不要每次请求都新建客户端，也不要登录态和出口各走各的（后一点到[第 5 章](ch05-proxy-pool.md)再钉死）。

自检：未带会话拿不到的 Demo 接口，带上之后能拿到；过期后你知道该刷新还是该停。大规模账号池、JWT 专项见第 7 章和崔庆才模拟登录章，此处只要求「一条会话链路通」。

## 3.8 出门考：自建 Demo 的列表 + 详情

在**你控制**的站点上（本地静态页、自写的小服务、或书面授权的练习环境）独立完成下面全部，中间可以查文档，但不能跳过：

1. 说明列表数据来自 HTML 还是接口（3.2）。
2. 用 `httpx` + 一种选择器拉列表，写入一种可 Diff 的存储（3.3、3.5）。
3. 对每条进入详情（或详情接口），主键不重复（3.6）。
4. 若详情需登录：用同一会话跑通（3.7）。
5. 用一句话决定要不要 Playwright（3.4）。
6. 全程遵守限速；把一次失败做成「可解释」（状态码、是否重试）。

通过即可进入第二部分。失败的那一节，回到参考书补完再考一次，不必在本书第 3 章加页。
