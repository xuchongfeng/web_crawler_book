# 第 14 章 加固认知与教学壳

[第 13 章](ch13-static-tools.md)在明文 DEX 上走出了「路径 → 调用点」。加壳之后，那条路会断在 stub：jadx 里几乎没有业务类，搜索路径没有命中。本章要讲清：壳在解决什么、**基本原理和类型**、对静态阅读与采集各改变什么、下一步换构建 / 换协议 / 换设备还是停手。类型旁边的「手段」是采集工程怎么应对，不是脱壳步骤。

实验对象仍是第 1.5 节：自有 CI、自有上架包、合作测试包。商业加固怎么脱、内存里怎么 dump DEX，本章和第 1.5 节都不写；14.5 再划一次线。混淆（类名被改、控制流被打乱，但 DEX 仍在）是第 15 章，先分清再动手。

## 14.1 壳在解决什么

壳（packer / wrapper）把真 DEX 藏起来或加密，启动时再在进程里还原，再把控制权交给真正的 `Application`。产品侧常见动机：

- **抬高静态阅读成本。** 商店上的包用 jadx 直接打开，看不到业务代码。
- **完整性。** 改资源、重签、塞二次打包的广告模块，运行期对不上。
- **和环境绑在一起。** 部分壳带模拟器、调试器、证书固定相关检测，失败就不开业务网。

采集工程要分清：**壳保护的是客户端可读性，不是 HTTP 接口本身。** 列表请求仍可能在网络上；你看不见 Java 拼接，不代表没有合法客户端（Debug 未加固包、官方 API、服务端日志）。

和相邻概念的差别：

| | 你在包里看见什么 | 下一步 |
|--|------------------|--------|
| 未加固、未混淆 | 类名可读，字符串能搜到 | [第 13 章](ch13-static-tools.md) 主路径 |
| 仅混淆（第 15 章） | DEX 还在，名字是 `a.b.c` | 用 `mapping.txt` 或对照抓包字符串 |
| 加壳 | DEX 很少、Application 是 stub、业务字符串搜不到 | 本章：换包，而不是脱壳 |
| 逻辑在 so 里 | Java 只有 `native` 声明 | 第 17 章；对象仍是自研 so |

辨认用现象，不靠猜厂商广告词：Manifest 的 `android:name` 指向一看就不像你们包名的 Application；`classes.dex` 很小；`lib/` 里多了与业务无关的 wrapper so。记下来即可。类型怎么分、每种对应什么手段，见 14.2。不要对着类名去搜「一键脱壳」。

## 14.2 原理、类型与对应手段

**原理（启动链）。** 未加固时：系统读 Manifest 里的 `Application`，加载 `classes.dex`，再走你们的 `onCreate`。加壳后这条链被拦腰插入一层：

1. Manifest 指向 **stub Application**（壳的代码）。
2. 真正的 DEX 不在明文 `classes.dex` 里，而是加密、拆碎或改写成自定义字节码，放在额外文件、`assets` 或 so 里。
3. stub 在启动时 **还原** 出可执行的 DEX（或把抽空的方法补回来），再加载，最后把控制权交给真正的 Application。
4. 往往同时做完整性校验、环境检测。失败则不初始化网络栈——你看到的是「不发请求」，不是 jadx 里多了几行。

壳改的是**进程里何时出现明文代码**，一般不改服务端路径。所以第 9 章抓包和第 13 章读包会分道：流量还在，DEX 不在。

「第几代壳」是社区俗称，厂商产品常把几档叠在一起，不要用广告词去对号入座。下表按**你在包里看见的机制**分；**手段**一列只写本书允许的应对。

| 类型（俗称） | 原理 | 静态上像什么 | 本书的手段 |
|--------------|------|--------------|------------|
| 整体加密、落盘加载（常叫一代） | 真 DEX 加密存放；运行时解密后写到应用私有目录，再 `DexClassLoader` 加载 | stub + 很小的 `classes.dex`；可能有高熵的额外文件 | 14.4 的教学壳就是这一档的笨版本。分析用 `demo-plain` / 关加固 CI。不要去翻设备上的解密文件——那是脱壳作业 |
| 整体加密、内存加载（常叫二代） | 解密后尽量不落盘，在内存中加载 DEX | 同样是 stub，磁盘上更找不到明文 DEX | 同上：换未加固构建。内存 dump 不写（14.5） |
| 函数抽取 / 指令抽空（常叫三代） | 方法体被掏空或改成 `native`；运行时再回填真指令 | jadx 能看到类名框架，方法是空的或一跳进 so | 换「未抽取」的构建或源码。不写回填点、不写怎么把空方法补回去 |
| 虚拟机保护 VMP（常叫四代） | 关键逻辑改成自定义字节码，由壳的解释器执行 | 反编译更无意义，控制流是解释循环 | 不要还原解释器。换协议、换构建或停手（14.3） |
| Java2C / 逻辑进 so | 签名、编解码直接编进 native | Java 只剩 `native` 声明 | 第 17 章，且只分析自研 / 教学 so |
| 资源 / 清单保护 | 加密 `res`、assets，或干扰 apktool | 解码资源失败；DEX 未必加密 | Host 和列表仍可能在网络里；配置对服务端或 `demo-plain`。不要为了资源去修 apktool |
| 配套检测（常与上面叠用） | 模拟器、调试器、重签、用户 CA | 包能打开，但挂代理或不发业务请求 | 换授权真机 / Debug 构建 / 服务端日志。不写绕过检测、不写 unpinning |

读表的方法：先看现象落在哪一行，再走「手段」列。**不要**把「一代 → 某 dump 工具、二代 → 某内存工具」当成下一列——那正是 14.5 不写的内容。商业产品往往「二代加载 + 三代抽取 + 检测」同时有；你只需判断：静态是否已死、请求还发不发、有没有未加固构建可换。

iOS 的 FairPlay、部分商店加密与 Android 壳不是同一套实现，纪律相同：不写砸壳、不写从内存抠出可执行文件。鸿蒙同理。

**静态因此怎么变。** 第 13 章的三板斧会同时失效：Analyzer 仍能看版本和 so 列表，但 jadx 搜不到路径，apktool 解出的 smali 只覆盖 stub（抽取壳则是空方法）。这不是工具坏了，是输入从「明文 DEX」变成了「加密或抽空的载荷」。JEB 同样吃明文；换更贵的 GUI 不会变出源码。历史未加固构建往往还能走 13.6，当前加固包则不要死磕。

**采集。** 协议采集依赖的是：合法会话、仍被服务端接受的路径和签名、能出网的设备。这些加壳后**可能还在**，也可能被壳附带的策略改掉：

- 中间人证书不被信任、或一挂代理就不发列表请求——先换 Debug 未加固构建或看服务端日志（[第 9.3 节](ch09-app-traffic.md)），不要去摘固定。
- 模拟器、Root、USB 调试被拒——换授权真机或你们实验室里允许的镜像（第 19 章），不要写绕过检测。
- 签名算法进 native、每次请求变——停在第 10.2 节的辨认；怎么算，只在未加固 Demo 或服务端校验代码上复现（[第 10.3 节](ch10-protocol.md)）。

判断句：**加壳让「读包」变难，不自动让「合法拉数」变难。** 反过来：能抓到包，也不等于该在壳上做对抗。任务元数据要多记一笔：是否加固、壳是否你们 CI 打的（第 18 章）。渠道包可能一份加壳一份不加，钉错渠道会表现为「同一版本有的能分析、有的不能」。

## 14.3 换协议 / 换设备 / 停手

看见壳，按这个顺序选，不要按「网上脱壳教程」选。

**换协议（优先）。** 未加固 Debug、同一仓库的 `demo-plain`、官方 / 合作 API、网关日志。第 12.4 节已经问过：接口稳定就不该为了专业去反编译。壳是再问一次同一句的理由。

**换构建。** CI 里出一枚关闭加固的 Release 或 Debug，哈希写进 10.1，再走第 13 章。13.6 的历史未加固包可以用来读懂协议，当前加固包用来确认「线上是否还接受同一套路径」。

**换设备。** 只在壳把「能发请求」和运行环境绑在一起时：授权真机、实验室镜像、对方提供的抓包环境。目的是让 Demo **发出**第 9 章那条列表请求，不是为了在这台设备上 dump。

**停手。** 同时满足下面几条，就停：对方只给商业加固包、书面范围不含分析、没有服务端日志或未加固构建、第 9–10 章也走不通。停手的产物是记录（现象、厂商若已知、授权缺口），不是半成品脱壳笔记。合作测试包的加固策略按对方红线：只读、禁止重打包，就不要「为了看清」去改包。

采集脚本不要依赖「先脱壳再跑」。合法客户端（你们的未加固包、官方 SDK、服务端签发的测试令牌）才是批量入口。

## 14.4 自研教学壳实验

要理解 14.1–14.2，用**自己写的、密钥写在仓库里的**教学壳，不要用商店里的商业壳当教具。案例预告见第 26.7 节。教学壳只实现表里「整体加密 + 落盘 `DexClassLoader`」那一档，好让第 13 章的失败可复现。

建议在 Demo 仓库打出两份 CI，同一 `versionCode`、同一测试服：

1. **`demo-plain`。** 普通 `Application`，第 13.5 节主路径能走通。
2. **`demo-shell`。** 自定义 stub `Application`：从 `assets` 读入你们自己加密的第二份 DEX，用公开的 `DexClassLoader`（或等价官方 API）加载后，把真正的 Application 交出去。加密用教学密钥（哪怕是 XOR），算法写在 README，不当秘密。

对照作业（不要 dump）：

| 观察 | `demo-plain` | `demo-shell` |
|------|----------------|----------------|
| jadx 搜列表路径 | 能落到拼请求的方法 | 只有 stub，路径搜不到 |
| 第 9 章抓包 | 有列表请求 | 形状应当相同（壳不该改协议） |
| 你如何「看清」代码 | 反编译或直接读仓库 | **读仓库和 `demo-plain`**，不是内存里的 DEX |

通过标准：能向别人讲清「静态断在哪、采集为什么还能做、为什么不需要 dump」。把 `demo-shell` 当脱壳靶子、练习从进程里掏 DEX，就是在练本书明确不写的技能，即便对象是自己的包也不要做。

教学壳保持愚蠢：不要加反调试、不要模仿商业厂商的 so 名字、不要做成可套到任意 APK 上的「通用加壳工具」。它只为了让第 13 章的失败可复现。

## 14.5 不覆盖商业加固脱壳与内存 dump

与[第 1.5 节](ch01-how-to-read.md)和第 8 章同一条边界，这里写死，后文（第 16.4、17.4 节、附录 E）只引用，不展开步骤。

**不写：**

- 针对梆梆、乐固、360、爱加密等**商业壳**的脱壳步骤、工具用法、修补点。
- 内存 dump、从 `/proc` 或匿名内存抠 DEX、对 `InMemoryDexClassLoader` 下钩子把明文写盘。
- 绕过壳的反调试、反 dump、完整性校验、证书固定（unpinning）。
- 把教学壳或 Frida 作业应用到第三方商店包。

**为什么不写。** 这些步骤的对象一旦换成未授权的生产 App，就是在拆别人的客户端保护；写进书里无法保证读者只打 Demo。采集要的是合法协议和授权身份，不是一份从别人进程里抠出来的 `classes.dex`。

**名词可以出现。** 后文若提到 dump、脱壳、unpinning，只解释那是什么、为什么本书停手，不接「然后你这样做」。

合作方若要求「必须分析加固包且不允许提供未加固构建」，请他们给抓包通道、服务端日志或书面允许的阅读范围。超出范围的对抗，不是采集工程的职责。

出门考（自有 Demo：一份 plain、一份教学壳，同一测试服）：

1. 用现象说明 `demo-shell` 被加了壳，并指出它落在 14.2 表的哪一类（教学壳应是整体加密 + 落盘加载）；对应手段是读仓库 / `demo-plain`，不是 dump。
2. 两份包各抓一次列表：写出协议是否相同；若 shell 包因环境检测没发出请求，你选择了换设备还是换 plain 构建，而不是绕过检测。
3. 写出 14.3 的决策：换协议 / 换构建 / 换设备 / 停手，四选一并说明原因。
4. 声明：没有对商业加固包做脱壳或内存 dump，也没有把教学壳套到第三方 APK 上。

通过即可。下一章处理「DEX 还在、只是读不懂」：混淆辨认与还原，对象仍是自有包。
