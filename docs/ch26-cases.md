# 第 26 章 案例集

十条都套[第 25 章](ch25-case-template.md)六格。实验环境：许可明确的开放数据、自建站点与 Demo App、合同内测试号与实验室设备。公开线索只说明「社区和文档在讨论什么现象或哪一层架构」，步骤以本书正文为准。

看雪等论坛里与 26.3、26.7 同题的帖子，多数在写商店包对抗；本章**不复述那些步骤**，只把现象映射到换 Debug、教学壳或停手。

## 26.1 开放数据增量

| 格 | 内容 |
|----|------|
| 目标 | 许可明确的开放目录（如 CKAN 类门户）做增量同步：只拉取上次水位之后变更的数据集元数据 |
| 约束 | 遵守门户条款与 API Key 权限；不扫未开放的库；敏感字段按对方许可存储 |
| 选型 | 官方 Action API / harvest，协议 worker，直连或机房即可 |
| 架构 | 种子=`package_search` 过滤 `metadata_modified`；水位进仓储；guid 去重后 upsert |
| 指标 | 增量条数、重复率、API `429`、水位回退告警 |
| 翻车 | 用页码翻全量导致漏插或重入；对方同一时间戳一整页造成死循环。改成按 id 排序并去重（CKAN harvest 源码里的取舍） |

**公开线索：** [ckanext-harvest](https://github.com/ckan/ckanext-harvest) 用 `metadata_modified:[since TO *]` 做增量，gather / fetch / import 三阶段。对应本书第 10.4、21.2 节。

## 26.2 自建商城接口

| 格 | 内容 |
|----|------|
| 目标 | 自己的练习商城：商品列表 + 详情，主键不重复 |
| 约束 | 只打本机或内网 Demo；不把淘宝级站点当练习场 |
| 选型 | 先 Network 找 JSON（第 3.2 节），`httpx` + 一种选择器；能接口就不开浏览器 |
| 架构 | 列表种子 → 详情；JSON Lines / SQLite；限速按主机 |
| 指标 | 两页成功、主键冲突为零、解析器黄金集绿 |
| 翻车 | 把 HTML 壳当数据源，选择器随改版全灭。先接口后渲染 |

**公开线索：** 各类「商城爬虫入门」博客几乎都从列表页 CSS 写起；稳定 JSON 才是第 3.2 节正路。对应第 3、23 章。

## 26.3 Demo App 协议

| 格 | 内容 |
|----|------|
| 目标 | 自有 Debug App 列表接口写成 10.1 文档，脚本只读拉两页 |
| 约束 | CI 制品或自有上架包；签名只在服务端校验代码上复现 |
| 选型 | 服务端日志优先；否则 Debug `network_security_config` + 实验 CA + mitm；Frida 仅打自己的规范化日志 |
| 架构 | 抓包 → 变化字段表 → 单测 HMAC → worker 钉 `versionCode` |
| 指标 | 抓包 / 日志 / 脚本三份 `sign` 一致；Release 中间人失败不计入「要揭秘」 |
| 翻车 | Release + pinning 时 TLS 握手失败、客户端直接关连接。社区笔记里常见 `certificate_unknown`、未发 HTTP 就断开。本书对策：换 Debug 或看网关，不摘固定（第 9.3、16.4 节） |

**公开线索：** [看雪](https://bbs.kanxue.com/)「抓包学习笔记」一类帖会归纳 Android 7 起默认不信任用户 CA、以及 pinning 导致握手失败。那是**现象分类**；论坛里同时存在的 unpinning / 商店 App 实战，不进本案例。对应第 9–11、16 章。

## 26.4 最小代理池

| 格 | 内容 |
|----|------|
| 目标 | 对 Demo 回显练习 `acquire` / `report` / `release`，粘性窗口内出口不变 |
| 约束 | 代理来自合同或自建；校验只打自己的 echo；免费公开列表不进池 |
| 选型 | 单进程内存池即可，不必先上 Redis |
| 架构 | 与 `httpx.Client` 同生共死；冷却键 `(出口, 域名)` |
| 指标 | 租约泄漏为零、校验失败率、每成功请求成本 |
| 翻车 | 多线程抢同一条代理、失败不 `report` 导致分数撒谎。工程博客里的 acquire/release 与锁，和[第 5 章](ch05-proxy-pool.md)同构 |

**公开线索：** 中文工程文常用 Redis 分数与「用完归还」；供应商文会导向住宅轮换过检。本案例只保留租约形状，过 WAF 序列不写。

## 26.5 验证码告警与人审

| 格 | 内容 |
|----|------|
| 目标 | Demo 上故意提高频率，让挑战页出现；系统告警并停自动解题 |
| 约束 | 不打码打第三方线上题；人审只处理你们自己的测试闸门 |
| 选型 | `report error=challenge`；路由停在协议层，升人工不升 Agent |
| 架构 | 看板挑战率与成功率分列；工单关闭前任务暂停 |
| 指标 | 触发率（主指标）、人审 SLA、解题费用应为零 |
| 翻车 | 把挑战当 OCR 作业，费用涨而触发率不降 |

对应[第 6 章](ch06-captcha.md)、第 24.2 节。

## 26.6 自建站测试账号池 + 会话

| 格 | 内容 |
|----|------|
| 目标 | 三种角色（游客 / 邮箱测试号 / 可选测试短信通道）租约化，登录后拉需登录列表 |
| 约束 | 号只来自第 7 章；禁止接码成品号 |
| 选型 | 账号租约与出口成对；同一 `httpx.Client` |
| 架构 | `acquire` 角色 → 登录 → 拉数 → `release`；Token 不进仓储 |
| 指标 | 池空排队次数、会话过期错误、绑定拆开导致的挑战 |
| 翻车 | 每个请求新 Client 丢 Cookie；或合法号中途换出口 |

对应第 7、5.3、8 章。

## 26.7 教学壳与分析回流

| 格 | 内容 |
|----|------|
| 目标 | `demo-plain` 与 `demo-shell` 对照：静态断在 stub，抓包协议仍同；结论写进 10.1 与钉扎 |
| 约束 | 教学壳密钥在仓库；禁止对商业壳 dump、禁止套到第三方 APK |
| 选型 | 整体加密 + 落盘 `DexClassLoader`（第 14.4 节）；分析用 plain 与源码 |
| 架构 | 两份 CI → jadx 现象表 → 回流 18.1 |
| 指标 | shell 包路径搜不到；两包列表请求形状一致 |
| 翻车 | 把 shell 当脱壳靶子练内存抠 DEX。看雪近年高频帖在讲自定义 linker、隐藏 so、mmap 后再可执行——那是**商业壳为什么静态读不动**的现象。本书手段仍是换未加固构建，不写钓 so、修 ELF |

**公开线索：** 看雪 Android 安全版块大量「加固 / 壳 / 隐藏 SO」讨论，与第 14.2 节类型表同构。个人博客亦有「教学向自定义 linker」原理文。步骤以第 14、18 章为准，不外链对抗贴。

## 26.8 设备农场 + 授权号

| 格 | 内容 |
|----|------|
| 目标 | N≥3 台（USB / 合同云手机 / Debug 模拟器）各绑不同授权号，拉两页；掉机回收锁 |
| 约束 | 不用随机设备信息过检；不把群控对准未授权 App |
| 选型 | 设备租约 + 账号租约；协议优先，UI 只短触发 |
| 架构 | 心跳 → `acquire` → 对齐钉扎包 → 绑定 → 执行 → 成对 `release` |
| 指标 | 在线率与采集成功分列；锁泄漏；掉机后其余台继续 |
| 翻车 | ADB 并发过高掉线；云手机端口每次启动都变却写死；登录态飘到另一台机。测试圈文档会提心跳、端口转发、ADB 线程上限——取运维，不取「改机对抗」 |

**公开线索：** 云真机 / Airtest 连云手机的排障文（端口、unauthorized、心跳超时）可对照第 19.2、20.2 节。模拟器多开文里「随机设备信息规避风控」是第 19.5 节反模式，本案例禁用。

## 26.9 改版：规则 vs 规则+LLM

| 格 | 内容 |
|----|------|
| 目标 | Demo 列表改版一次：规则黄金集变红；旁路模型只抽失败样本，敏感字段脱敏 |
| 约束 | 默认规则；模型日配额；原文不上公有云（第 23.3 节） |
| 选型 | CSS/JSON 规则先跑；字段空且非挑战页才进模型；CI 门槛不达标不部署 |
| 架构 | 同一 Schema；Diff 新旧解析器；血缘记解析器版本 |
| 指标 | 黄金集匹配率、模型调用次数与费用、规则修复后模型占比应下降 |
| 翻车 | 每页都送 LLM，账单先爆；或模型胡填价格而 CI 没有精确匹配。英文工程博客的共识是：选择器零边际成本、LLM 抗改版但按次计费，混合且用校验兜底 |

**公开线索：** 如「LLM extraction vs CSS selectors」一类 2026 年前后的综述：稳定页用选择器，结构动荡再用模型；Hilgard 等强调静默抽错比崩溃更危险——对应黄金集，而不是 Agent 一把梭。

## 26.10 最小采集平台

| 格 | 内容 |
|----|------|
| 目标 | 单机：任务 API + 一个协议 worker + 看板；提交自建列表任务，拒绝允许名单外的 URL |
| 约束 | 无 K8s 也可；密钥不进镜像 |
| 选型 | 第 22.4 节出门考原样；执行器默认协议 |
| 架构 | 闸门 → 队列 → worker（租约）→ 仓储 → 五列看板 |
| 指标 | 非法目标拒绝率、调度 ID 可点进失败、演练停队列成功 |
| 翻车 | 红了自动升代理档或自动跟最新包。先按 22.3 停写入 |

对应第 21–22 章，并作为第 25 章模板的「整系统」样例。
