# 第 1 章 怎么读这本书

本书面向**已经会写一点程序**的人：你用过 HTTP 客户端，知道 HTML 或 JSON 长什么样，不一定做过采集系统。它不是又一本「从 urllib 讲到四种解析库」的工具说明书，也不是法律教材。

读这一章是为了三件事：知道本书按什么能力拆问题、你该从哪一页开始、哪些事本书不会教。

第 2 章会把「难在哪里」画成地图；第 3 章是精简基础，会了就跳。有经验的读者读完 1.4、1.5 即可进入第二部分。

## 1.1 能力模型：协议 / 设备 / 调度 / 数据 / 合规

把采集当成五个互相咬合的能力，而不是「会不会写脚本」。缺一块，系统会在别的地方崩。

**协议。** 目标到底以什么形状给数据：网页、Ajax JSON、gRPC、Protobuf、长连接。先判断「有没有稳定接口」，再决定要不要开浏览器或真机。网页选择器、App 抓包、签名字段辨认，都落在这一层。对应第四部分、第五部分的协议与分析。

**设备。** 有些数据只在特定客户端、特定会话、特定出口上才出现。真机、模拟器、云手机、浏览器配置文件，解决的是「以谁的身份、从哪台机器出发」。设备不是为了堆并发刷量，而是为了可复现的实验环境。对应第六部分。

**调度。** 种子从哪来、任务谁先跑、失败怎么重试、何时该降级（协议 → 浏览器 → 真机 → 人工）。代理池的分配、账号租约、按域名的并发上限，都是调度问题。对应第二部分、第七部分。

**数据。** 抓回来只是开始：字段是否完整、能否重放、如何去重与增量、进哪一种存储。没有血缘的数据，改版之后无法证明「上一版是对的」。对应第 3 章的最小存储，以及第七、八、九部分。

**合规。** 能连通 ≠ 能采集 ≠ 能保存 ≠ 能再分发。账号从哪来、数据含不含个人信息、合同和平台规则允不允许，决定项目能不能上线。这一能力贯穿全书，专章在第 1.4、第 7–8 章和附录 D。

五块不必每人做深。一个人可以先做协议，一个团队需要五块都有人负责。本书按这个模型排章节，方便你对号入座。

## 1.2 三条路线与本书权重

同一份需求，常见有三条路。本书**不平均用力**。

| 路线 | 典型工作 | 本书态度 |
|------|----------|----------|
| Web 采集 | 列表/详情、接口、偶发浏览器 | 压成第 3 章自检 + 附录对照，不展开成工具百科 |
| App 协议采集 | 抓包、还原自有接口、版本钉扎 | 主线之一，第四部分加厚 |
| 设备与规模化 | 真机实验室、代理池、任务平台、观测 | 主线之一，第二、六、七部分加厚 |

另外还有两条横切线，不单独当「第三条职业路线」，但会反复出现：

- **账号与身份**（第三部分）：只用你拥有或被授权的测试号。
- **AI**（第八部分）：规则优先、模型兜底；不当成「Agent 一把梭」。

**建议读法：**

- 写过爬虫、主要补 App / 出口 / 系统：第 1 章红线 → 第 2 章地图 → 从[第 4 章](ch04-egress.md)读起。
- 会 Python、没系统做过采集：第 1–3 章按顺序，第 3 章出门考过了再进第二部分。
- 只查某一块：用第 2.8 节跳转表（第 2 章），或目录页。

基础知识建议用这两本书补：崔庆才《Python3网络爬虫开发实战》覆盖面广、偏工具步骤；Mitchell《Python网络爬虫权威指南》偏模型和抓取思路。请求、解析、存储、Scrapy 入门等，本书第 3 章只做自检，不展开复述。对照细表见附录 C。本书把篇幅留给出口、账号边界、App 协议、客户端分析、设备实验室、规模化和 AI 工作流。

## 1.3 何时不该爬

动手之前先问：数据是不是已经有更干净的来源。下面几种情况，**默认不爬**。

**官方 API 或开放数据门户够用。** 有文档、有配额、有稳定性承诺时，自建采集是在重复造一个更脆的轮子。

**合作导出或采购更合适。** 商务数据、批量历史库、需要授权的字段，走合同和接口，比在客户端里还原更可审计。

**你没有权限碰这个系统。** 别人的生产 App、未授权的后台、需要破解才能看的接口，不是实验对象。本书所有操作默认发生在自建靶场、自有 Demo、或书面授权的测试环境。

**数据主要是个人信息或敏感个人信息。** 即使技术上能抓到，保存和再加工通常受《个人信息保护法》等约束。没有合法基础（同意、合同必要、法定职责等）就不要建库。

**你只能靠「过验证码 / 换号 / 换设备」才能继续。** 这通常说明对方已经把你当成风险流量。先停，查出口、限速和授权，而不是加一层对抗。

**结果不能合规使用。** 即使抓下来了，若不能用于分析、不能给客户、不能公开，这个项目在业务上已经失败。第 2.7 节会展开「能抓 ≠ 能用」。

不确定时，把「不爬」写成默认选项，把「爬」写成需要理由的例外。

## 1.4 法律与平台规则清单

本节是**工程师检查表**，不是法律意见。上线前应咨询你们的法务；跨境还要看数据出境与当地法律。

在中国大陆做采集，至少要能回答这些问题（对应法规名称供检索，不在这里复述条文）：

1. **网络安全与系统安全。** 是否未经授权访问、是否对他人系统造成干扰或破坏。相关讨论常见于《网络安全法》以及刑法中计算机信息系统相关罪名。
2. **数据分类。** 是否涉及个人信息、重要数据、核心数据。《数据安全法》《个人信息保护法》要求你说清楚处理目的、范围、期限和安全措施。
3. **竞争秩序。** 抓取是否不正当地获取他人经营数据、是否破坏机器人协议或访问控制，可能落到《反不正当竞争法》等争议里。已有公开判决围绕数据抓取、账号滥用、破坏技术措施。
4. **合同与平台规则。** 用户协议、开发者协议、robots.txt、API 配额。违反合同不一定等于犯罪，但足够让账号封禁、民事诉讼、合作终止。
5. **行业许可。** 征信、地图、新闻、金融等行业另有准入，不因「我只会写爬虫」而豁免。

**平台规则（每次换目标都要重看）：**

- 是否禁止自动化访问、禁止多开、禁止模拟客户端。
- 测试账号、沙箱、官方采集接口是否存在。
- 频率、日配额、User-Agent 或开发者身份要求。

**记录习惯：** 每个任务写明数据来源、授权依据、字段清单、保留期限。第七部分讲血缘和重放时，会用到这些记录。

本书案例一律落在自建站点或开放许可数据上，避免把「某商业 App 实战」写成可复制的进攻说明书。

## 1.5 实验纪律与本书不写清单

**实验纪律**

- 代码和流量只打向：本机 Demo、你控制的靶场、书面授权的测试环境、许可明确的开放数据。
- App 分析只用：自己的 CI 制品、自己上架的包、合作方提供的测试包。
- 账号只用：你注册并拥有的测试号、企业测试通道、合同约定的账号。邮箱用自有域名或公司测试箱；短信用云厂商给**你自己产品**的测试号。
- 保留抓包、版本号、配置，保证别人按文档能复现——复现的是你的 Demo，不是别人的生产环境。
- 验证码、风控页、封禁，当作**观测信号**：降并发、换授权出口、或停手，而不是当作要「解开」的谜题。

**本书不写（后文遇到相关名词，只解释是什么、为什么不能做）**

- 针对商业加固的脱壳步骤、内存 dump、绕过证书固定、绕过反调试。
- 用 Frida、unidbg 等从**第三方** so 里提取密钥或签名算法。
- 接码平台、海外号源获取、养号节奏、对第三方站点的批量自动注册。
- 打码平台用于通过他人线上验证码。
- 未授权的群控刷量、设备指纹造假、伪造 TLS/浏览器画像以穿过 WAF 的操作序列。

第五部分会讲 jadx、Frida、JNI 和「教学壳」，实验对象都是**你能控制两端的 Demo**。第三部分[第 8 章](ch08-abuse-lines.md)专门讲账号滥用红线。附录 E 会再列一份更短的「不写清单」方便检索。
