# 第 5 章 代理池

第 4 章解决「买哪种出口」。本章把出口收成系统：谁进池、怎么验、怎么打分、任务怎么借和还。没有这套手续，你只是在脚本里写死了一个代理字符串，扩起来一定乱。

池解决的是**容量、隔离和可观测**，不是「换得勤就能过风控」。伪造画像去过 WAF，本书不写（第 1.5 节）。打自建 Demo，直连往往够；上池是为了练习租约，或你已经有权、需要多出口的授权任务。

供应商的「隧道」已经在云端换 IP 时，你的池仍然有用：这时池管的是**产品 / 会话槽**，不是一长串 `host:port`。两种形态共用同一套 `acquire` / `release` / `report`。

## 5.1 采集、校验、评分、分配、冷却

五段流水，缺一段都会在扩容时爆。

**采集。** 入口只有你说得清来源的地址：自建机房、合同里的供应商 API、自己的宽带实验出口。每条记录至少有：连接串或隧道会话参数、类型（机房 / ISP / …）、地域、协议、成本标签、写入时间。按 `host:port` 或供应商会话 ID 去重。免费公开列表不进池（第 4.5 节）。

**校验。** 进池或定期抽检，只打**你控制的回显**（本机小服务、内网 echo、书面授权的健康页），不要拿未授权商业站当探针。至少确认：

- 流量确实走了代理，回显里的出口 IP 不是本机。
- 出口 ASN / 网段和宣传类型对得上（第 4.3 节）。
- 延迟和连通可接受；`SOCKS5` 没有静默直连。
- 声明了粘性的，窗口内连续两次回显应是同一出口。

失败的先隔离，不要发给任务。校验失败率突然升高，优先查供应商和你的网络，而不是加大轮换。

**评分。** 分数是给分配器用的，不是「反检测分」。建议按**域名**记，而不是只有全局平均：同一条出口在站点 A 可用、在站点 B 被限，很常见。可用信号：成功率、延迟分位、单位流量成本、最近一次失败类型。`429`、超时、连接失败和「页面变成挑战」不要合成一个数字——后一种交给[第 6 章](ch06-captcha.md)当信号，不要自动理解成「再换一条就好」。

**分配。** 按任务约束发货：类型、地域、要粘性多久、协议。没有约束时，便宜且分数够用的先走。同一租约在过期前不要借给第二个任务。池空了应排队或降级（5.4），不要默默直连却还以为自己在走代理。

**冷却。** 某条出口在某个域名上刚失败，短时间内不要再发给同一域名。冷却键是 `(出口, 域名)`，不是只冻整条出口——除非校验证明它已经死了。硬失败（认证错、连接拒绝）进隔离，等下次校验；软失败（偶发超时）短冷却即可。

这五段可以先做同步、单进程。队列、多机协调是第七部分的事。

## 5.2 acquire / release / report

对外只暴露三件事，内部状态不要渗进爬虫脚本。

```python
lease = pool.acquire(
    domain="demo.example",
    sticky_seconds=300,      # 0 表示这条请求用完即还
    egress_class="datacenter",
    region="cn",
)
# lease.proxy_url / lease.session_id
# ... 发请求 ...
pool.report(lease, ok=True, status=200, error=None, bytes_out=1200)
pool.release(lease)
```

**`acquire`。** 按约束选出一条可用出口，加上租约：到期时间、绑定的域名、是否粘性。拿不到就抛明确错误或返回「请降级」，不要返回 `None` 让调用方猜。粘性窗口从这里开始计时，和 Cookie、浏览器 Context 的寿命对齐（5.3）。

**`report`。** 每次（或每批）请求回来后记账：状态码、耗时、流量、错误类型。评分、冷却、预算都只认 `report`，不认日志里的形容词。一次租约可以 `report` 多次，最后再 `release`。

**`release`。** 归还。未到期的粘性租约，同一任务可以续借；换任务必须先还。进程崩溃要有超时回收，否则池会被租约耗尽。凭证（代理密码、隧道 token）跟租约走，用完从工作内存里丢掉，保管习惯见[第 7.9 节](ch07-accounts.md)。

调用纪律：

- 先 `acquire` 再发请求；禁止脚本里另写一套代理字符串「抄近道」。
- `report` 与 `release` 放在 `finally`，成功失败都要还。
- 不要在业务代码里根据「像不像被封」私自换出口；要换，通过再次 `acquire` 或 5.4 的降级，并留下 `report`。

账号租约（[第 7 章](ch07-accounts.md)）和设备租约（第 19 章）建议同一形状：都是 acquire / report / release。出口只是第一种租约。

## 5.3 与请求栈 / 浏览器 / 设备出口绑定

身份是绑在一起算的（第 2.3 节）。租约的边界就是会话的边界。

**`httpx`。** 一条粘性租约配一个 `httpx.Client`（或 AsyncClient），`proxy` 只在构造时注入。不要每个 `GET` 换代理却复用同一份 Cookie 罐。客户端关的时候 `release`。

**浏览器。** Playwright 里一个 `BrowserContext` 一条粘性出口：创建 Context 时传入 `proxy`，Cookie、本地存储、出口同生共死。新任务、新登录，开新 Context，重新 `acquire`。不要多个 Context 共享一条粘性住宅会话「省钱」，除非你有意让它们在对方眼里是同一个人。

**设备。** 真机或云手机的出口是设备属性：网卡、该设备上的系统代理、或机房为这台设备固定的线路。池按**设备**发租约，不要在同一台已登录的设备上中途改代理（第 19 章）。云手机若供应商已绑定出口，你的池记录的是设备 ID，而不是再套一层随机住宅。

**对照：**

| 栈 | 和租约一起生灭的东西 |
|----|----------------------|
| `httpx.Client` | Cookie 罐、TCP 连接、代理 URL |
| Playwright `BrowserContext` | Cookie、存储、代理 |
| 真机 / 云手机 | 设备会话、该设备出口 |
| 供应商隧道 | 会话 ID（粘性参数）与这次任务 |

排障时日志至少能回答：这条请求用了哪条租约、出口 IP 是什么、对应哪个 Context 或设备。对不上，先修绑定，再谈评分。

## 5.4 指标、预算、按域名降级

池没有看板，就只会在账单或封禁之后被人发现。

**指标（按域名切一刀）：** 成功率、`429`/`403`/挑战页比例、延迟分位、在借租约数、冷却中的出口数、校验失败率、每成功动作的费用（第 2.6 节）。全局平均数会掩盖「只有一个域名在烧钱」。

**预算。** 每个域名（或每条产品线）设日/月上限和默认出口等级。默认走直连或机房；只有任务配置允许、且便宜等级连续失败时，才升到更贵的 ISP / 住宅。升档是例外，要写进配置，不要写进某个 if 的临时判断。预算用尽：排队、降 QPS 或停，而不是自动去买来路不明的池。

**按域名降级**（先慢，再换，再停）：

1. 限速、加长退避（第 3.6 节）。
2. 冷却当前出口，`acquire` 同等级的下一条。
3. 升一档出口类型——仅当授权与预算允许。
4. 出挑战页：当信号，不要在这里「解题」（第 6 章）；人审或停手。
5. 熔断该域名：池还在，任务先不发。

直连够用的域名不要进代理预算。对方要的是登录或开发者协议时，换出口不能代替授权（第 4.4 节）。

## 5.5 最小可用代理池

先做一个能在自建靶场上跑通的最小闭环，不要上 Redis 集群。

**范围：**

- 存储：内存或 SQLite 一张表。
- 来源：两三条你自己的机房出口，或一家合同清楚的机房 / 隧道；另加「直连」作为零号出口。
- 回显：本机或内网一个返回出口 IP 的接口，供校验。
- 接口：5.2 的三个方法；冷却键 `(出口, 域名)`；进程退出时超时回收租约。
- 调用方：一个 `httpx.Client` 脚本，对 Demo 拉列表。打开 Playwright 时，Context 与租约成对创建、成对关掉。

**不必现在做：** 多机锁、自动采购、按 ASN 智能画像、住宅自动升档、和账号池混部。那些分别属于第七部分、第 4.5 节采购和第 7 章。

出门考：

1. 画出五段流水，标出你的数据存在哪、校验打谁。
2. 用伪代码写出 `acquire` / `report` / `release`，并说明一次粘性登录翻页里，这三下各调用几次。
3. 给 Demo 配「直连 → 机房粘性 → 停」的降级，跑一次故意的失败（停掉一条出口），看板能看出冷却和预算变化。
4. 写明：浏览器 Context 和租约谁先建、谁后拆。

通过即可进第 6 章。第 6 章把验证码和挑战页当成上游已经可疑的信号，而不是池的评分缺口。
